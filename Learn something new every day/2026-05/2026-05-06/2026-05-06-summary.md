## 🏗️ System Design / Architecture
- ⭐ **[Shopify GraphQL Cardinal — breadth-first execution engine (12/03)](https://shopify.engineering/faster-breadth-first-graphql-execution)**
  **Đây là gì:** GraphQL conventional resolve **depth-first** (mỗi object, đi sâu xuống từng field) — N+1 query là hệ quả. Shopify build **Cardinal**, engine **breadth-first**: resolve **mỗi field 1 lần cho toàn bộ object cùng type**. Kiến trúc: build execution tree với "scope" (typed closure) + field từ AST → planning bottom-up cho phép field register preload từ ancestor → breadth execution (resolver nhận **set object đầy đủ**, trả mapped result, flat-map sang scope kế tiếp) → queue-driven thay recursion để giảm stack/memory → kết quả pass by reference assemble in-place. Số liệu: **15× nhanh hơn, 90% ít memory hơn** cho list query lớn, tiết kiệm >4 giây tại P50.
  **Vì sao đáng đọc:** đây là case study mẫu cho việc **đổi cách lặp** (depth-first → breadth-first) thay vì caching/optimize từng query. Joy nếu có resolver GraphQL-style trên Cloud Functions trả list lớn (orders + customers + rewards) → mindset breadth-first (batch-fetch theo field, không theo object) cắt rõ rệt cold-DB-call. Cũng là reference cho khái niệm "scope" trong execution engine — design pattern hay cho bất kỳ tree traversal có context inheritance.
