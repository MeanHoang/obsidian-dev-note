Patch ở Commerce 2205.49 / 2211.51 / 2211-jdk21.10 (xem [NVD detail](https://nvd.nist.gov/vuln/detail/CVE-2026-34263)). **Impact Joy Loyalty:** Joy không dùng SAP Commerce, nhưng đây là case study tốt về cách rule order trong Spring Security (hoặc bất kỳ middleware/policy engine nào — bao gồm Firebase Security Rules) có thể tạo lỗ hổng auth bypass khi devs để rule "allow" rộng đứng trước rule "require auth" — review lại Firestore rules có pattern tương tự không.

## 🏗️ System Design / Architecture

- ⭐ **[Rethinking Distributed Systems for Serverless Performance and Reliability](https://www.databricks.com/blog/rethinking-distributed-systems-serverless-performance-and-reliability)** ([Databricks Eng Blog](https://www.databricks.com/blog/rethinking-distributed-systems-serverless-performance-and-reliability))
  **Đây là gì:** Bài 06/05/2026 của Aaron Davidson + team Databricks mô tả 3 trụ cột để build serverless compute thực sự: (1) Spark Connect tách client app khỏi compute infra theo mô hình client-server, (2) intelligent gateway route workload dựa trên query size + cluster utilization + latency profile, (3) adaptive autoscaler analyze workload pattern, scale ngang/dọc tự động, biến stability thành thuộc tính hệ thống thay vì việc user phải lo.
  **Vì sao đáng đọc:** Joy cũng kiểu serverless (Cloud Run + Functions), bài này dạy mindset "stability is a system property, not user responsibility" — áp dụng khi thiết kế batch sync orders/loyalty events: gateway phân loại sync nặng/nhẹ trước khi đẩy vào worker pool.

- **[7 Architectural Patterns After An On-Call Meltdown](https://technori.com/2026/05/25686-7-architectural-patterns-after-an-on-call-meltdown/marcus/)** ([technori.com, May 2026](https://technori.com/2026/05/25686-7-architectural-patterns-after-an-on-call-meltdown/marcus/))
  **Đây là gì:** Bài phân tích hệ thống fail khác đi khi team vượt qua mức "hành lang giao tiếp" — coordination chậm hơn, process overhead nhiều hơn, và team né operational boundary quá lâu sẽ tích "invisible reliability debt".
  **Vì sao đáng đọc:** Joy đang lớn dần, mindset này áp dụng khi quyết định khi nào tách module loyalty/billing/event-stream thành service riêng — chậm tách thì on-call burnout, sớm tách thì coordination cost.

## 🌐 Web Development

- **[Chrome 148 stable: `loading="lazy"` cho `<video>` và `<audio>`, defer load media tới gần viewport](https://developer.chrome.com/release-notes/148)** ([Chrome release notes, cập nhật 05/05/2026](https://developer.chrome.com/release-notes/148))
  **Đây là gì:** Chrome 148 stable thêm thuộc tính `loading="lazy"` cho `<video>` / `<audio>` (lâu nay chỉ `<img>` + `<iframe>` có) — defer media resource load tới khi element gần vào viewport, giảm initial page load và data usage. Trang chỉ render media khi user kéo tới.
  **Vì sao đáng đọc:** widget loyalty page hoặc storefront onboarding video lâu nay tự load ngay khi user vào page, ảnh hưởng LCP. Bây giờ chỉ cần thêm 1 attribute là cải thiện Core Web Vitals, không cần JS lazy-load thủ công.
