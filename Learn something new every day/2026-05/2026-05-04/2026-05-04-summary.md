## 🏗️ System Design / Architecture
- ⭐ **[Decoupled DiLoCo: Resilient, Distributed AI Training at Scale](https://deepmind.google/blog/decoupled-diloco/)** (Google DeepMind, 23/04)
  **Đây là gì:** kiến trúc training LLM trên nhiều data center cách xa địa lý, chia thành các "island" compute chạy bất đồng bộ — nếu 1 island hỏng, các island khác vẫn tiếp tục. Số liệu: bandwidth giảm từ 198 Gbps xuống **0.84 Gbps** giữa 8 datacenter, productivity giữ **88%** trong scenario lỗi cao (so với 27% của method synchronous), train được model 12B param trên 4 region Mỹ "nhanh hơn 20×". Build trên prior work Pathways + DiLoCo.
  **Vì sao đáng đọc:** dù không train LLM, đây là case study mẫu mực cho **async distributed system** — dùng làm reference khi thiết kế bất kỳ pipeline phải tolerate partial failure (event processing, points calculation queue, cross-region replication). Concept "isolated islands + async data flow" áp dụng được cho Pub/Sub fan-out hoặc background job multi-tenant.

- **[7+ Google Firestore Query Performance Best Practices for 2026](https://estuary.dev/blog/firestore-query-best-practices/)** (Estuary, cập nhật 05/03)
  **Đây là gì:** tổng hợp 7 best practice cho Firestore query: **single-field index exemption** (disable index cho field không query), tránh large collection/document (giới hạn query 10 MiB), denormalization + aggregation precompute, pagination + sharding, batched read, offline persistence + cache aggressively (Firebase SDK có sẵn) để giảm billable read.
  **Vì sao đáng đọc:** Firestore cost của Joy chủ yếu là **read operations**, không phải storage. Single-field index exemption là switch nhanh cắt write cost cho field như `updatedAt`/`syncedAt` không bao giờ filter — đôi khi giảm 30-40% write index spend.

## 🌐 Web Development
- **[Bun vs Node.js benchmark 2026 (Strapi, cập nhật 20/04)](https://strapi.io/blog/bun-vs-nodejs-performance-comparison-guide)**
  **Đây là gì:** đo benchmark thực tế Bun vs Node.js. **Synthetic HTTP**: Bun ~52,000 req/s vs Node ~13,000 req/s (gấp 4×). **Real-world app** (có DB + routing): chênh lệch chỉ <3%. **Cold start AWS Lambda**: Bun 290ms vs Node 940ms (nhanh 69%). **Install large monorepo**: npm 28 phút, pnpm 4 phút, Bun 47 giây (35× nhanh hơn npm). Memory: Bun ít hơn 25-40% cho API server, ~26% cho Next.js. CPU-bound: Bun nhanh ~2×.
  **Vì sao đáng đọc:** synthetic benchmark đẹp lệch xa real-world. **Lý do thật để chọn Bun**: cold start (Cloud Run scaling từ 0) + install speed (CI cycle), không phải req/s. Joy dùng Cloud Functions/Run → cold start 290ms vs 940ms = SLO p99 dễ thở hơn rất nhiều.

  **Đây là gì:** Shopify từng thông báo từ **04/05/2026** (hôm nay): khi customer cancel subscription mà không còn subscription active nào khác → **payment method bị invalidate sau 24h**.   **Vì sao đáng đọc:** nếu Joy hoặc đối tác có app subscription mà đã viết code ứng phó (re-tokenize trước cancel, gửi email warning cho customer…) → **rollback hoặc hold release**. Cũng là case mẫu cho việc Shopify đôi khi hủy breaking change vào phút chót — đừng ship code ứng phó breaking change quá sớm.
- **[April 29, 2026 Updates to the Admin Polaris Library — đã rollback](https://community.shopify.dev/t/april-29-2026-updates-to-the-admin-polaris-library/33804)**
  **Đây là gì:** Polaris team release update lớn (cải thiện 13 component: Checkbox, Modal, DatePicker, Select…, giảm CSS bundle ~2.2%) vào 29/04. Nhanh chóng bị merchant report **missing button, layout shift, modal không hoạt động** → Shopify rollback. Cộng đồng phàn nàn về **lack of version pinning** cho web components — extension không thể "pin" Polaris version, luôn dùng latest từ CDN.
  **Vì sao đáng đọc:** Joy build Admin/Customer Account UI extension → hiểu rõ pattern Polaris có thể đẩy regression vào prod bất ngờ. Mitigation: snapshot test cho UI critical, chạy E2E hàng ngày trên dev store thay vì chỉ on-demand.
- **[Shopify CLI bỏ flag `--force` trong tháng 5/2026](https://shopify.dev/changelog)**
  **Đây là gì:** flag `--force` bị deprecate để chống xoá nhầm app extension. Thay bằng `--allow-updates` cho deploy intentional update.
  **Vì sao đáng đọc:** check CI/CD script Joy ngay — script auto-deploy có thể fail thầm khi `--force` biến mất. Replace bằng `--allow-updates` trước khi pipeline đỏ.
