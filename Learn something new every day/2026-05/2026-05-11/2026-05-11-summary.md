# News Summary — 2026-05-11

## 🔥 Top 3 đáng đọc nhất

1. **[Shopify yêu cầu bot/agent identify qua Web Bot Auth — Storefront API siết rate limit (07/05, hiệu lực 30/05)](https://shopify.dev/changelog/bots-and-agents-should-identify-themselves-via-web-bot-auth)** — Đây là gì: Web Bot Auth là chuẩn IETF cho bot ký request bằng HTTP signature, để server biết "đây là bot X đáng tin" thay vì user-agent dễ giả mạo. Từ 30/05/2026, Shopify áp **rate limit chặt nhất** cho bot không ký request truy cập Storefront API + page online store. Bot có ký Web Bot Auth → rate limit cao hơn; merchant tự crawl shop của mình có sẵn signature trong admin. **Impact Joy Loyalty:** nếu Joy có job nào crawl storefront (preview email, SEO check, sync product), phải implement Web Bot Auth trước 30/05 không thì throttle nặng. Nếu chỉ gọi Admin API thì không ảnh hưởng.

2. **[Firebase App Check sắp bật replay attack protection — token strictly single-use](https://firebase.google.com/docs/app-check/web/custom-resource)** — Đây là gì: App Check là tính năng Firebase chứng minh request đến từ app thật (không phải script). Trước giờ token App Check có hiệu lực ~1 giờ, attacker chộp được vẫn dùng lại được. Update từ tháng 5/2026: bật **replay protection** thì token chỉ dùng 1 lần — backend phải verify + consume token. Để xài, client gọi `getLimitedUseToken()` thay vì `getToken()`, server dùng Admin SDK consume. **Impact Joy Loyalty:** nếu có Cloud Functions hoặc custom backend bảo vệ bằng App Check (vd webhook nhận từ Joy storefront app, API ghi/đọc loyalty point), nên migrate sang `getLimitedUseToken()` ngay — tới khi GA bật replay protection sẽ tự kế thừa, tránh phải patch gấp.

3. **[Shopify thêm Publishable interface cho ProductVariant — publish/unpublish từng variant theo channel (07/05)](https://shopify.dev/changelog)** — Đây là gì: trước đây publish/unpublish chỉ làm ở mức product (cả product hiện hoặc ẩn trên 1 sales channel). Update cho `ProductVariant` implement `Publishable` interface → control hiển thị **từng variant trên từng channel/catalog** mà không cần duplicate product hay xoá variant. Mặc định variant vẫn published, nhưng channel không hỗ trợ product feed thì cần update implementation. **Impact Joy Loyalty:** không tác động trực tiếp loyalty logic, nhưng đáng note nếu Joy có flow tặng quà "exclusive variant cho VIP tier" — giờ có thể ẩn variant đó khỏi channel public, chỉ show ở channel/catalog dành riêng cho tier cao. Cũng giảm code workaround dùng metafield hide-by-channel.
