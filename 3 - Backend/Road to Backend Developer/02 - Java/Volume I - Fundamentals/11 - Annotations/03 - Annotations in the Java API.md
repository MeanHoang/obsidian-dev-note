## 11.3. Annotations in the Java API

> *"The Java API defines a number of annotation interfaces in the java.lang, java.lang.annotation, and javax.annotation packages. Four of them are meta-annotations that describe the behavior of annotation interfaces. The others are regular annotations that you can use to annotate items in your source code. Table 11.2 shows these annotations. I will discuss them in detail in the following two sections."*

**Dịch:** Java API định nghĩa **một loạt annotation interface** trong các package **`java.lang`, `java.lang.annotation` và `javax.annotation`**. **Bốn trong số đó là meta-annotation** mô tả hành vi của annotation interface. **Số còn lại là annotation thông thường** bạn dùng để annotate item trong source code của mình.

### Table 11.2: Annotations in the Java API

| Annotation Interface | Applicable To | Purpose | Dịch |
|---|---|---|---|
| `Override` | Methods | Checks that this method overrides a superclass method. | Kiểm tra rằng method này **override một method của superclass** |
| `Serial` | Methods | Checks that this method is a correct serialization method. | Kiểm tra rằng method này là **serialization method đúng chuẩn** |
| `Deprecated` | All declarations | Marks item as deprecated. | Đánh dấu item là **deprecated** |
| `SuppressWarnings` | All declarations except packages | Suppresses warning messages of a given type. | **Tắt các warning message** thuộc một loại cho trước |
| `SafeVarargs` | Methods and constructors | Asserts that the varargs parameter is safe to use. | Khẳng định rằng **varargs parameter dùng an toàn** |
| `FunctionalInterface` | Interfaces | Marks an interface as functional (with a single abstract method). | Đánh dấu một interface là **functional** (chỉ có **một abstract method**) |
| `Generated` | All declarations | Marks an item as source code that has been generated by a tool. | Đánh dấu item là **source code do một tool sinh ra** |
| `Target` | Annotations | Specifies the locations to which this annotation can be applied. | Chỉ định **những vị trí mà annotation này áp được lên** |
| `Retention` | Annotations | Specifies where this annotation can be used. | Chỉ định **nơi annotation này dùng được** |
| `Documented` | Annotations | Specifies that this annotation should be included in the documentation of annotated items. | Chỉ định rằng annotation này **nên được đưa vào documentation** của các item được annotate |
| `Inherited` | Annotations | Specifies that this annotation is inherited by subclasses. | Chỉ định rằng annotation này **được subclass kế thừa** |
| `Repeatable` | Annotations | Specifies that this annotation can be applied multiple times to the same item. | Chỉ định rằng annotation này **áp được nhiều lần lên cùng một item** |

## 11.3.1. Annotations for Compilation

### `@Deprecated`

> *"The @Deprecated annotation can be attached to any items whose use is no longer encouraged. The compiler will warn when you use a deprecated item. This annotation has the same role as the @deprecated JavaDoc tag. However, the annotation persists until runtime."*

**Dịch:** `@Deprecated` **gắn được lên bất kỳ item nào mà việc dùng nó không còn được khuyến khích**. Compiler sẽ **cảnh báo khi bạn dùng một item deprecated**. Annotation này **cùng vai trò với tag JavaDoc `@deprecated`** (xem [[10 - Documentation Comments]]). Tuy nhiên, **annotation thì tồn tại tới tận runtime**.

> **Note (sách):** *"The jdeprscan utility which is part of the JDK can scan a set of JAR files for deprecated elements."*
>
> **Dịch:** Tiện ích **`jdeprscan`** trong JDK **quét được một tập file JAR để tìm các element deprecated**.

### `@Override`

> *"The @Override annotation makes the compiler check that the annotated method really overrides a method from the superclass. For example, if you declare"*

```java
public class Point
{
    @Override public boolean equals(Point other) { . . . }
    . . .
}
```

> *"then the compiler will report an error—this equals method does not override the equals method of the Object class because that method has a parameter of type Object, not Point."*

**Dịch:** `@Override` **bắt compiler kiểm tra rằng method được annotate thực sự override một method từ superclass**. Với khai báo trên, **compiler sẽ báo lỗi** — method `equals` này **không override method `equals` của class `Object`**, vì method đó có **parameter kiểu `Object`, không phải `Point`**.

### `@Serial`

> *"The @Serial annotation checks that methods used for serialization, which are not declared in interfaces, have the correct parameter types."*

**Dịch:** `@Serial` **kiểm tra rằng các method dùng cho serialization** — vốn **không được khai báo trong interface nào** — **có đúng kiểu parameter**.

### `@SuppressWarnings`

> *"The @SuppressWarnings annotation tells the compiler to suppress warning messages of a particular category, for example"*

```java
@SuppressWarnings("unchecked") T[] result
    = (T[]) Array.newInstance(cl, n);
```

**Dịch:** `@SuppressWarnings` **bảo compiler tắt các warning message thuộc một hạng mục cụ thể**.

### `@SafeVarargs`

> *"The @SafeVarargs annotation asserts that a method does not corrupt its varargs parameter (see Chapter 8)."*

**Dịch:** `@SafeVarargs` **khẳng định rằng một method không làm hỏng varargs parameter của nó** (xem Chapter 8 — [[09 - Reflection and Generics]]).

### `@Generated`

> *"The @Generated annotation is intended for use by code generator tools. Any generated source code can be annotated to differentiate it from programmer-provided code. For example, a code editor can hide the generated code, or a code generator can remove older versions of generated code. Each annotation must contain a unique identifier for the code generator. A date string (in ISO 8601/RFC 3339 format) and a comment string are optional. For example,"*

```java
@Generated(value="com.horstmann.generator",
    date="2015-01-04T12:08:56.235-0700");
```

**Dịch:** `@Generated` **dành cho các code generator tool dùng**. **Mọi source code được sinh ra đều annotate được** để **phân biệt với code do lập trình viên viết**. Ví dụ, một code editor có thể **ẩn phần code được sinh ra**, hoặc một code generator có thể **xoá các phiên bản cũ của code được sinh ra**. **Mỗi annotation phải chứa một định danh duy nhất cho code generator.** Một **chuỗi ngày tháng** (theo định dạng **ISO 8601/RFC 3339**) và một **chuỗi comment** là **tuỳ chọn**.

### `@FunctionalInterface`

> *"You have seen the FunctionalInterface annotation in Chapter 6. It is used to annotate conversion targets for lambda expressions, such as"*

```java
@FunctionalInterface
public interface IntFunction<R>
{
    R apply(int value);
}
```

> *"If you later add another abstract method, the compiler will generate an error. Of course, you should only add this annotation to interfaces that describe functions. There are other interfaces with a single abstract method (such as AutoCloseable) that are not conceptually functions."*

**Dịch:** Bạn đã thấy annotation `FunctionalInterface` ở Chapter 6 ([[01 - Interfaces]]). Nó dùng để **annotate các đích chuyển đổi cho lambda expression**. Nếu sau này bạn **thêm một abstract method nữa, compiler sẽ báo lỗi**. Tất nhiên bạn **chỉ nên thêm annotation này vào những interface mô tả function**. Còn có những interface khác **cũng chỉ có một abstract method** (như `AutoCloseable`) nhưng **về khái niệm không phải là function**.

## 11.3.2. Meta-Annotations

> *"You have already seen the @Target and @Retention meta-annotations in Section 11.2."*

**Dịch:** Bạn đã thấy meta-annotation `@Target` và `@Retention` ở Section 11.2 ([[02 - Defining Annotations]]).

### `@Documented`

> *"The @Documented meta-annotation gives a hint to documentation tools such as JavaDoc. Documented annotations should be treated just like other modifiers (such as private or static) for documentation purposes. In contrast, other annotations should not be included in the documentation."*

**Dịch:** Meta-annotation `@Documented` **đưa gợi ý cho các documentation tool như JavaDoc**. Annotation được documented thì **nên được đối xử y như các modifier khác** (kiểu `private` hay `static`) khi làm tài liệu. Ngược lại, **các annotation khác không nên được đưa vào documentation**. Xem [[10 - Documentation Comments]].

> *"For example, the @SuppressWarnings annotation is not documented. If a method or field has that annotation, it is an implementation detail that is of no interest to the JavaDoc reader. On the other hand, the @FunctionalInterface annotation is documented since it is useful for the programmer to know that the interface is intended to describe a function. Figure 11.1 shows the documentation."*

**Dịch:** Ví dụ, `@SuppressWarnings` **không được documented**. Nếu một method hay field mang annotation đó thì **đấy là chi tiết implementation, người đọc JavaDoc chẳng quan tâm**. Ngược lại, `@FunctionalInterface` **có được documented**, vì lập trình viên **biết được interface này nhằm mô tả một function là điều hữu ích**.

### `@Inherited`

> *"The @Inherited meta-annotation applies only to annotations for classes. When a class has an inherited annotation, then all of its subclasses automatically have the same annotation. This makes it easy to create annotations that work similar to marker interfaces (such as the Serializable interface)."*

**Dịch:** Meta-annotation `@Inherited` **chỉ áp dụng cho annotation dành cho class**. Khi một class **mang một annotation inherited**, thì **mọi subclass của nó tự động có cùng annotation đó**. Nhờ vậy **dễ tạo ra những annotation hoạt động tương tự marker interface** (như interface `Serializable`).

> *"Suppose you define an inherited annotation @Persistent to indicate that objects of a class can be saved in a database. Then the subclasses of persistent classes are automatically annotated as persistent."*

```java
@Inherited @interface Persistent { }

@Persistent class Employee { . . . }
class Manager extends Employee { . . . } // Also @Persistent
```

**Dịch:** Giả sử bạn định nghĩa một **inherited annotation `@Persistent`** để báo rằng object của class đó **lưu được vào database**. Khi ấy **subclass của các class persistent tự động được annotate là persistent**.

### `@Repeatable`

> *"The @Repeatable meta-annotation makes it possible to apply the same annotation multiple times. For example, the JUnit @Tag annotation is repeatable. It can be used like this:"*

```java
@Tag("localized")
@Tag("showstopper")
void testHello() { . . . }
```

**Dịch:** Meta-annotation `@Repeatable` **cho phép áp cùng một annotation nhiều lần**. Ví dụ annotation `@Tag` của JUnit là **repeatable**.

> *"For historical reasons, the implementor of a repeatable annotation needs to provide a container annotation that holds the repeated annotations in an array. Here is how to define the @Tag annotation and its container:"*

```java
@Repeatable(Tag.class)
@interface Tag
{
    String value();
}

@interface Tags
{
    Tag[] value();
}
```

**Dịch:** **Vì lý do lịch sử**, người implement một repeatable annotation **phải cung cấp thêm một container annotation** giữ các annotation lặp lại **trong một array**.

> *"Whenever the user supplies two or more @Tag annotations, they are automatically wrapped into a @Tags annotation. This complicates processing of the annotation, as you will see in the next section."*

**Dịch:** **Hễ người dùng đưa vào hai `@Tag` trở lên, chúng tự động được gói vào một annotation `@Tags`.** Điều này **làm việc xử lý annotation phức tạp hơn**, như bạn sẽ thấy ở section sau.
