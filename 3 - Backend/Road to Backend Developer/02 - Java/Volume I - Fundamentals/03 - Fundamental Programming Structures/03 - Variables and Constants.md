## Ví dụ đời sống: Khai báo biến = Dán nhãn hộp

Tưởng tượng bạn có **kho hàng** (bộ nhớ). JS cho bạn lấy hộp bất kỳ, bỏ gì vào cũng được — số, chữ, cả con mèo. Java thì khác: **mỗi hộp phải dán nhãn loại hàng trước** — hộp ghi "giày" thì chỉ chứa giày, bỏ áo vào là bị từ chối ngay tại quầy (compile error).

| Kho hàng | Hộp (biến) | Nhãn (type) |
|---|---|---|
| JS | `let box = "shoes"` → `box = 42` ✅ | Không cần nhãn, đổi kiểu tuỳ ý |
| Java | `String box = "shoes"` → `box = 42` ❌ | Phải dán nhãn, không đổi kiểu được |

## 3.4.1 Declaring Variables — Khai báo biến

> *"In Java, every variable has a type. You declare a variable by placing the type first, followed by the name of the variable."*

**Dịch:** Mọi biến trong Java **phải có kiểu**. Khai báo bằng cách đặt **kiểu trước**, tên biến sau.

```java
double salary;
int vacationDays;
long earthPopulation;
boolean done;
```

So sánh với JS — đặt keyword (`let`/`const`/`var`) trước, **không cần kiểu**:

```js
let salary;        // kiểu gì? — chưa biết, runtime mới biết
let vacationDays;  // cũng chưa biết
```

Java bắt bạn **cam kết kiểu ngay từ đầu** → compiler biết biến chiếm bao nhiêu byte, nhận giá trị gì.

### Quy tắc đặt tên biến

> *"The identifier for a variable name is made up of letters, digits, currency symbols, and 'punctuation connectors.' The first character cannot be a digit."*

> *"A letter is any Unicode character that denotes a letter in a language. For example, German users can use umlauts such as ä in variable names; Greek speakers could use a π."*

**Dịch:** Tên biến gồm chữ cái, số, ký hiệu tiền tệ (`$`, `€`...), dấu nối (`_`). Ký tự đầu **không được là số**. Java chấp nhận **Unicode** (chữ Đức, Hy Lạp, cả tiếng Việt), nhưng thực tế: **cứ dùng A-Z, a-z, 0-9 và `_`**.

Vài lưu ý quan trọng:

> *"Even though $ is a valid character in an identifier, you should not use it in your own code. It is intended for names that are generated by the Java compiler and other tools."*

**Dịch:** `$` hợp lệ nhưng **đừng dùng** — nó dành cho code do compiler sinh ra (anonymous class, lambda...).

> *"However, a single underscore _ is a reserved word."*

**Dịch:** Dấu gạch dưới đơn `_` là [[Glossary#R|reserved word]] (từ Java 9+). Từ Java 21 (preview), `_` dùng làm **unnamed variable** — biến bắt buộc khai báo nhưng không cần dùng (sẽ gặp ở Chapter 6, 7).

### Không khai báo nhiều biến trên 1 dòng

> *"I don't recommend this style. If you declare each variable separately, your programs are easier to read."*

```java
int i, j;          // ❌ hợp lệ nhưng khó đọc
int i;             // ✅ mỗi biến 1 dòng
int j;
```

> 💡 **JS cũng vậy** — ESLint rule `one-var` khuyên `let a; let b;` thay vì `let a, b;`.

## 3.4.2 Initializing Variables — Khởi tạo biến

> *"After you declare a variable, you must explicitly initialize it by means of an assignment statement—you can never use the value of an uninitialized variable."*

**Dịch:** Khai báo xong **phải gán giá trị trước khi dùng**. Nếu không → **compile error**. Đây không phải runtime crash — Java **từ chối biên dịch luôn**.

```java
int vacationDays;
System.out.println(vacationDays); // ❌ COMPILE ERROR — chưa khởi tạo
```

```java
int vacationDays;
vacationDays = 12;                // ✅ gán rồi mới dùng

// Hoặc gọn hơn:
int vacationDays = 12;            // ✅ khai báo + khởi tạo cùng lúc
```

Đây chính là triết lý **[[02 - The Java White Paper Buzzwords#1.2.4 Robust|Robust]]** (bài 1.2.4) — bắt lỗi càng sớm càng tốt, **compile time tốt hơn runtime**.

> 💡 **JS:** `let x; console.log(x);` → chạy bình thường, in `undefined`. Không lỗi, nhưng dễ gây bug ngầm — bạn dùng `undefined` mà không biết. Java chặn từ gốc.

### Khai báo gần nơi sử dụng

> *"In Java, it is considered good style to declare variables as closely as possible to the point where they are first used."*

**Dịch:** Khai báo biến **ngay gần chỗ dùng** — không dồn hết lên đầu method. Giống nguyên tắc "declare close to use" mà JS developer cũng áp dụng khi chuyển từ `var` sang `let`.

```java
double salary = 65000.0;
System.out.println(salary);
int vacationDays = 12;  // ← khai báo ở đây, không phải đầu method
```

### `var` — Type inference (Java 10+)

> *"You do not need to declare the types of local variables if they can be inferred from the initial value. Simply use the keyword var instead of the type."*

```java
var vacationDays = 12;       // compiler suy ra: int
var greeting = "Hello";      // compiler suy ra: String
```

**⚠️ `var` Java ≠ `var` JS — rất khác nhau!**

| | `var` trong Java (10+) | `var` trong JS (ES3) |
|---|---|---|
| **Ý nghĩa** | **Type inference** — compiler tự suy kiểu | **Function-scoped declaration** — khai báo biến |
| **Scope** | Block scope (giống `let` JS) | **Function scope** (hoisting lên đầu function) |
| **Bắt buộc init?** | ✅ phải gán ngay (không có giá trị thì suy kiểu gì?) | ❌ `var x;` hợp lệ |
| **Đổi kiểu?** | ❌ — kiểu cố định sau khi suy ra | ✅ — `var x = 1; x = "abc";` |
| **Tương đương** | Gần giống TypeScript `let x = 12` (type inferred) | Không có tương đương Java |

```java
var count = 10;    // kiểu là int — CỐ ĐỊNH
count = "hello";   // ❌ COMPILE ERROR — int không gán String được
```

```js
var count = 10;    // kiểu dynamic
count = "hello";   // ✅ JS cho phép — var chỉ là cách khai báo
```

> 💡 Nếu từ JS sang Java, hãy hiểu `var` Java giống **TypeScript inference** hơn là `var` JS. Nó chỉ giúp **viết ngắn hơn**, **không thay đổi bản chất strongly typed**.

## 3.4.3 Constants — Hằng số (`final`)

> *"In Java, you use the keyword final to denote a constant."*

> *"The keyword final indicates that you can assign to the variable once, and then its value is set once and for all. It is customary to name constants in all uppercase."*

**Dịch:** `final` = gán **1 lần duy nhất**, sau đó không đổi được. Quy ước đặt tên: **ALL_UPPERCASE** với underscore.

```java
final double CM_PER_INCH = 2.54;
CM_PER_INCH = 3.0;  // ❌ COMPILE ERROR — cannot assign to final variable
```

**So sánh: `final` (Java) vs `const` (JS)**

| | `final` (Java) | `const` (JS) |
|---|---|---|
| Gán lại? | ❌ | ❌ |
| Mutate object? | ✅ `final list` vẫn `add()` được | ✅ `const arr` vẫn `push()` được |
| Scope | Block | Block |

Giống hệt: cả hai chặn **reassign** nhưng **không chặn mutation** bên trong object. `final List<String> names` vẫn `names.add("Bob")` được — giống `const arr = []; arr.push(1)` trong JS.

### Class constants: `static final`

> *"It is probably more common in Java to create a constant so it's available to multiple methods inside a single class. These are usually called class constants. Set up a class constant with the keywords static final."*

```java
public class Constants2 {
    public static final double CM_PER_INCH = 2.54;  // class constant

    public static void main(String[] args) {
        double paperWidth = 8.5;
        System.out.println(paperWidth * CM_PER_INCH);
    }
}
```

**Dịch:** `static final` = hằng số **cấp class**, dùng được ở mọi method trong class. Nếu thêm `public` thì class khác cũng truy cập được: `Constants2.CM_PER_INCH`.

> 💡 **JS tương đương:** Không có `static final` chính xác, nhưng pattern gần nhất:
> ```js
> // Module-level constant (dùng khắp file)
> const CM_PER_INCH = 2.54;
> export { CM_PER_INCH };  // class khác import được
> ```

### `const` keyword tồn tại nhưng không dùng

> *"const is a Java keyword, but it is not currently used for anything. You must use final for a constant."*

**Dịch:** `const` là **reserved word** trong Java nhưng **không có chức năng**. Đừng dùng — Java dùng `final`.

## 3.4.4 Enumerated Types — Kiểu liệt kê (`enum`)

> *"Sometimes, a variable should only hold a restricted set of values. For example, you may sell clothes or pizza in four sizes: small, medium, large, and extra large. Of course, you could encode these sizes as integers 1, 2, 3, 4 or characters S, M, L, and X. But that is an error-prone setup. It is too easy for a variable to hold a wrong value (such as 0 or m)."*

**Dịch:** Khi biến chỉ nên chứa **một tập giá trị cố định** (size áo, trạng thái đơn hàng...), dùng số nguyên hay ký tự thì **dễ sai** — gán nhầm `0` hay `"m"` mà compiler không bắt được.

### Ví dụ đời sống: Enum = Menu nhà hàng

Nhà hàng có **4 size** đồ uống: S, M, L, XL. Nếu ghi bằng số (1, 2, 3, 4) trên phiếu order → nhân viên mới ghi nhầm `5` hoặc `0` → sai mà không ai biết. Nếu in sẵn **4 ô checkbox** (S / M / L / XL) → chỉ tick được 1 trong 4, **không thể sai**.

- **Menu checkbox** = `enum` trong Java
- **Viết số tự do** = dùng `int` constant → dễ sai
- **Code:**

```java
// ❌ Dùng int — compiler không biết 5 là sai
int size = 5;  // compiles OK, nhưng 5 không phải size hợp lệ!

// ✅ Dùng enum — compiler chặn giá trị ngoài danh sách
enum Size { SMALL, MEDIUM, LARGE, EXTRA_LARGE }
Size s = Size.MEDIUM;    // ✅
Size s = Size.HUGE;      // ❌ COMPILE ERROR — HUGE không tồn tại
```

> *"An enumerated type has a finite number of named values."*

```java
enum Size { SMALL, MEDIUM, LARGE, EXTRA_LARGE };
Size s = Size.MEDIUM;
```

> *"A variable of type Size can hold only one of the values listed in the type declaration, or the special value null that indicates that the variable is not set to any value at all."*

**Dịch:** Biến kiểu `Size` chỉ chứa được giá trị **trong danh sách đã khai báo**, hoặc `null`. Không gì khác.

### So sánh với JS

JS không có `enum` native. Các pattern thay thế:

```js
// Pattern 1: Object freeze (phổ biến nhất)
const Size = Object.freeze({
    SMALL: "SMALL",
    MEDIUM: "MEDIUM",
    LARGE: "LARGE",
    EXTRA_LARGE: "EXTRA_LARGE",
});
let s = Size.MEDIUM;     // ✅
let s2 = "HUGE";         // ✅ JS không chặn — runtime mới biết sai

// Pattern 2: TypeScript enum
enum Size { SMALL, MEDIUM, LARGE, EXTRA_LARGE }  // compile-time check
```

**Khác biệt cốt lõi:** Java `enum` là **type-safe** ở compile time — gán giá trị ngoài danh sách = compile error. JS `Object.freeze` chỉ ngăn mutation, **không ngăn gán giá trị sai kiểu**. TypeScript `enum` gần giống Java nhất.

> 💡 Enum sẽ được bàn chi tiết hơn ở Chapter 5. Ở đây chỉ cần hiểu: **enum = tập giá trị đóng, type-safe**.

## Tổng kết: Bảng so sánh Java vs JS

| Khái niệm | Java | JS |
|---|---|---|
| Khai báo biến | `int x = 5;` (type trước) | `let x = 5;` (keyword trước) |
| Biến chưa init | ❌ Compile error | ✅ `undefined` (bug ngầm) |
| Hằng số | `final` | `const` |
| Hằng cấp class | `static final` | `export const` (module-level) |
| Type inference | `var x = 5;` (Java 10+, block scope, type cố định) | `var x = 5;` (function scope, type dynamic) |
| Enum | `enum Size { S, M, L }` (type-safe) | `Object.freeze({...})` (không type-safe) |
| `const` keyword | Tồn tại nhưng **không dùng** | Khai báo hằng số |
