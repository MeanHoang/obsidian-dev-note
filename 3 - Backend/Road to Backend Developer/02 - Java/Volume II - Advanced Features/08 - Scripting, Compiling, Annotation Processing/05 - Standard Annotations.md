## 8.5. Standard Annotations

> *"A number of annotation interfaces are defined in the java.lang, java.lang.annotation, and javax.annotation packages. Four of them are meta-annotations that describe the behavior of annotation interfaces. The others are regular annotations that you can use to annotate items in your source code. Table 8.2 shows these annotations. We'll discuss them in detail in the following two sections."*

**Dịch:** Một số annotation interface được định nghĩa trong các package **`java.lang`, `java.lang.annotation`, và `javax.annotation`**. **Bốn trong số đó là meta-annotation** mô tả hành vi của annotation interface. Số còn lại là **annotation thông thường** để annotate item trong source code của bạn.

### Table 8.2 — The Standard Annotations

| Annotation Interface | Applicable To | Purpose |
|---|---|---|
| `Deprecated` | All | Marks item as deprecated. |
| `SuppressWarnings` | All but packages and annotations | Suppresses warnings of the given type. |
| `SafeVarargs` | Methods and constructors | Asserts that the varargs parameter is safe to use. |
| `Override` | Methods | Checks that this method overrides a superclass method. |
| `FunctionalInterface` | Interfaces | Marks an interface as functional (with a single abstract method). |
| `PostConstruct`<br>`PreDestroy` | Methods | The marked method should be invoked immediately after construction or before removal. |
| `Resource` | Classes, interfaces, methods, fields | On a class or interface, marks it as a resource to be used elsewhere. On a method or field, marks it for "injection." |
| `Resources` | Classes, interfaces | Specifies an array of resources. |
| `Generated` | All | Marks an item as source code that has been generated by a tool. |
| `Target` | Annotations | Specifies the items to which this annotation can be applied. |
| `Retention` | Annotations | Specifies how long this annotation is retained. |
| `Documented` | Annotations | Specifies that this annotation should be included in the documentation of annotated items. |
| `Inherited` | Annotations | Specifies that this annotation, when applied to a class, is automatically inherited by its subclasses. |
| `Repeatable` | Annotations | Specifies that this annotation can be applied multiple times to the same item. |

**Dịch bảng (cột Purpose):**

| Annotation | Công dụng |
|---|---|
| `Deprecated` | Đánh dấu item là **deprecated** |
| `SuppressWarnings` | **Chặn warning** thuộc loại đã cho |
| `SafeVarargs` | **Khẳng định varargs parameter dùng an toàn** |
| `Override` | **Kiểm tra method này có thật sự override một method của superclass** không |
| `FunctionalInterface` | Đánh dấu một interface là **functional** (chỉ có **một abstract method**) |
| `PostConstruct` / `PreDestroy` | Method được đánh dấu **nên được gọi ngay sau khi dựng xong** hoặc **ngay trước khi bị gỡ bỏ** |
| `Resource` | Trên class/interface: đánh dấu nó là **resource để dùng ở nơi khác**. Trên method/field: đánh dấu để **"injection"** |
| `Resources` | Chỉ định một **array các resource** |
| `Generated` | Đánh dấu item là **source code do một công cụ sinh ra** |
| `Target` | Chỉ định **những item mà annotation này áp được lên** |
| `Retention` | Chỉ định **annotation này được giữ lại bao lâu** |
| `Documented` | Chỉ định annotation này **nên được đưa vào tài liệu** của các item được annotate |
| `Inherited` | Chỉ định annotation này, khi áp lên một class, **tự động được subclass thừa hưởng** |
| `Repeatable` | Chỉ định annotation này **áp được nhiều lần lên cùng một item** |

## 8.5.1. Annotations for Compilation

> *"The @Deprecated annotation can be attached to any items whose use is no longer encouraged. The compiler will warn when you use a deprecated item. This annotation has the same role as the @deprecated Javadoc tag. However, the annotation persists until runtime."*

**Dịch:** `@Deprecated` **gắn được lên bất kỳ item nào mà việc dùng nó không còn được khuyến khích**. Compiler sẽ **cảnh báo khi bạn dùng một item deprecated**. Annotation này có **cùng vai trò với tag Javadoc `@deprecated`**, nhưng **annotation tồn tại tới tận runtime**. (Xem [[10 - Documentation Comments]] ở Volume I.)

> **Note (sách):** *"The jdeprscan utility that is part of the JDK can scan a set of JAR files for deprecated elements."*
>
> **Dịch:** Tiện ích **`jdeprscan`** trong JDK **quét được một tập file JAR để tìm element deprecated**.

> *"The @SuppressWarnings annotation tells the compiler to suppress warnings of a particular type, for example:"*

```java
@SuppressWarnings("unchecked")
```

**Dịch:** `@SuppressWarnings` **bảo compiler chặn warning thuộc một loại cụ thể**.

> *"The @Override annotation applies only to methods. The compiler checks that a method with this annotation really overrides a method from the superclass. For example, if you declare"*

```java
public MyClass
{
    @Override public boolean equals(MyClass other);
    . . .
}
```

> *"then the compiler will report an error. After all, the equals method does not override the equals method of the Object class because that method has a parameter of type Object, not MyClass."*

**Dịch:** `@Override` **chỉ áp được lên method**. Compiler **kiểm tra xem method mang annotation này có thật sự override một method của superclass hay không**. Ở ví dụ trên compiler **báo lỗi**: method `equals` kia **không override `equals` của class `Object`**, vì method đó **có parameter kiểu `Object`, không phải `MyClass`**.

> *"The @Generated annotation is intended for use by code generator tools. Any generated source code can be annotated to differentiate it from programmer-created code. For example, a code editor can hide the generated code, or a code generator can remove older versions of generated code. Each annotation must contain a unique identifier for the code generator. A date string (in ISO 8601 format) and a comment string are optional. For example,"*

```java
@Generated("com.horstmann.beanproperty", "2008-01-04T12:08:56.235-0700");
```

**Dịch:** `@Generated` **dành cho các công cụ sinh code dùng**. Source code sinh ra **được annotate để phân biệt với code do lập trình viên viết**. Ví dụ, một code editor có thể **ẩn code được sinh**, hoặc một code generator có thể **gỡ bỏ phiên bản cũ của code được sinh**. **Mỗi annotation phải chứa một identifier duy nhất cho code generator**; **chuỗi ngày (định dạng ISO 8601)** và **chuỗi comment** là **tuỳ chọn**.

## 8.5.2. Annotations for Managing Resources

> *"The @PostConstruct and @PreDestroy annotations are used in environments that control the lifecycle of objects, such as web containers and application servers. Methods tagged with these annotations should be invoked immediately after an object has been constructed or immediately before it is being removed."*

**Dịch:** `@PostConstruct` và `@PreDestroy` được dùng trong **những môi trường kiểm soát vòng đời của object**, như **web container và application server**. Method gắn các annotation này **nên được gọi ngay sau khi một object được dựng xong**, hoặc **ngay trước khi nó bị gỡ bỏ**.

> *"The @Resource annotation is intended for resource injection. For example, consider a web application that accesses a database. Of course, the database access information should not be hardwired into the web application. Instead, the web container has some user interface for setting connection parameters and a JNDI name for a data source. In the web application, you can reference the data source like this:"*

```java
@Resource(name="jdbc/mydb")
private DataSource source;
```

> *"When an object containing this field is constructed, the container "injects" a reference to the data source."*

**Dịch:** `@Resource` dành cho **resource injection**. Ví dụ một web application truy cập database: dĩ nhiên **thông tin truy cập database không nên bị gắn cứng vào web application**. Thay vào đó, **web container có giao diện để đặt connection parameter và một tên JNDI cho data source**. Khi một object chứa field này được dựng, **container "tiêm" (inject) một reference tới data source**.

## 8.5.3. Meta-Annotations

### `@Target`

> *"The @Target meta-annotation is applied to an annotation, restricting the items to which the annotation applies. For example,"*

```java
@Target({ElementType.TYPE, ElementType.METHOD})
public @interface BugReport
```

> *"Table 8.3 shows all possible values. They belong to the enumerated type ElementType. You can specify any number of element types, enclosed in braces."*

**Dịch:** Meta-annotation **`@Target` được áp lên một annotation**, **giới hạn những item mà annotation đó áp được lên**. Các giá trị thuộc **enumerated type `ElementType`**; bạn **chỉ định được bao nhiêu element type tuỳ ý, bọc trong ngoặc nhọn**.

### Table 8.3 — Element Types for the `@Target` Annotation

| Element Type | Annotation Applies To | Dịch |
|---|---|---|
| `ANNOTATION_TYPE` | Annotation type declarations | Khai báo annotation type |
| `PACKAGE` | Packages | Package |
| `TYPE` | Classes (including enum) and interfaces (including annotation types) | Class (kể cả `enum`) và interface (kể cả annotation type) |
| `METHOD` | Methods | Method |
| `CONSTRUCTOR` | Constructors | Constructor |
| `FIELD` | Fields (including enum constants) | Field (kể cả enum constant) |
| `PARAMETER` | Method or constructor parameters | Parameter của method hoặc constructor |
| `LOCAL_VARIABLE` | Local variables | Local variable |
| `TYPE_PARAMETER` | Type parameters | Type parameter |
| `TYPE_USE` | Uses of a type | Chỗ dùng một type |

> *"An annotation without an @Target restriction can be applied to any item. The compiler checks that you apply an annotation only to a permitted item. For example, if you apply @BugReport to a field, a compile-time error results."*

**Dịch:** Một annotation **không có giới hạn `@Target`** thì **áp được lên bất kỳ item nào**. Compiler **kiểm tra rằng bạn chỉ áp annotation lên item được cho phép**.

### `@Retention`

> *"The @Retention meta-annotation specifies how long an annotation is retained. You can specify at most one of the values in Table 8.4. The default is RetentionPolicy.CLASS."*

**Dịch:** Meta-annotation **`@Retention` chỉ định annotation được giữ lại bao lâu**. Bạn **chỉ định được nhiều nhất một giá trị**. **Mặc định là `RetentionPolicy.CLASS`.**

### Table 8.4 — Retention Policies for the `@Retention` Annotation

| Retention Policy | Description | Dịch |
|---|---|---|
| `SOURCE` | Annotations are not included in class files. | Annotation **không được đưa vào file class** |
| `CLASS` | Annotations are included in class files, but the virtual machine need not load them. | Annotation **được đưa vào file class**, nhưng **virtual machine không nhất thiết phải load chúng** |
| `RUNTIME` | Annotations are included in class files and loaded by the virtual machine. They are available through the reflection API. | Annotation **được đưa vào file class và được virtual machine load**. Chúng **truy cập được qua reflection API** |

> *"In Listing 8.8, the @ActionListenerFor annotation was declared with RetentionPolicy.RUNTIME because we used reflection to process annotations. In the following two sections, you will see examples of processing annotations at the source and class file levels."*

**Dịch:** Ở Listing 8.8 (xem [[03 - Using Annotations]]), annotation `@ActionListenerFor` được khai báo với **`RetentionPolicy.RUNTIME`** vì ta **dùng reflection để xử lý annotation** (xem [[10 - Reflection]] ở Volume I).

### `@Documented`

> *"The @Documented meta-annotation gives a hint to documentation tools such as Javadoc. Documented annotations should be treated just like other modifiers, such as protected or static, for documentation purposes. The use of other annotations is not included in the documentation. For example, suppose we declare @ActionListenerFor as a documented annotation:"*

```java
@Documented
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface ActionListenerFor
```

> *"Now the documentation of each annotated method contains the annotation, as shown in Figure 8.2."*

> *"If an annotation is transient (such as @BugReport), you should probably not document its use."*

**Dịch:** Meta-annotation **`@Documented` gợi ý cho các công cụ tài liệu như Javadoc**. Annotation được documented **nên được đối xử như các modifier khác** (kiểu `protected` hay `static`) **cho mục đích tài liệu**. **Việc dùng các annotation khác thì không được đưa vào tài liệu.** Nếu một annotation là **transient** (như `@BugReport`) thì **có lẽ không nên đưa việc dùng nó vào tài liệu**.

> **Figure 8.2 — Documented annotations** *(hình ảnh trong sách, không tái hiện được từ bản trích văn bản)*

> **Note (sách):** *"It is legal to apply an annotation to itself. For example, the @Documented annotation is itself annotated as @Documented. Therefore, the Javadoc documentation for annotations shows whether they are documented."*
>
> **Dịch:** **Áp một annotation lên chính nó là hợp lệ.** Ví dụ, annotation `@Documented` **chính nó được annotate là `@Documented`**. Nhờ vậy, tài liệu Javadoc cho annotation **cho biết chúng có được documented hay không**.

### `@Inherited`

> *"The @Inherited meta-annotation applies only to annotations for classes. When a class has an inherited annotation, then all of its subclasses automatically have the same annotation. This makes it easy to create annotations that work as marker interfaces, such as Serializable."*

**Dịch:** Meta-annotation **`@Inherited` chỉ áp cho annotation dành cho class**. Khi một class có một **inherited annotation**, thì **mọi subclass của nó tự động có cùng annotation đó**. Nhờ vậy **dễ tạo ra annotation hoạt động như marker interface**, chẳng hạn `Serializable`.

> *"In fact, an annotation @Serializable would be more appropriate than the Serializable marker interface with no methods. A class is serializable because there is runtime support for reading and writing its fields, not because of any principles of object-oriented design. An annotation describes this fact better than does interface inheritance. Of course, the Serializable interface was created in JDK 1.1, long before annotations existed."*

**Dịch:** Thực ra một **annotation `@Serializable` sẽ hợp lý hơn** so với marker interface `Serializable` **không có method nào**. Một class serializable được là **vì có hỗ trợ runtime để đọc và ghi field của nó**, **không phải vì nguyên tắc thiết kế hướng object nào cả**. **Annotation mô tả thực tế đó tốt hơn interface inheritance.** Dĩ nhiên, interface `Serializable` được tạo ra ở **JDK 1.1**, **rất lâu trước khi có annotation**.

> *"Suppose you define an inherited annotation @Persistent to indicate that objects of a class can be saved in a database. Then the subclasses of persistent classes are automatically annotated as persistent."*

```java
@Inherited @interface Persistent { }
@Persistent class Employee { . . . }
class Manager extends Employee { . . . } // also @Persistent
```

> *"When the persistence mechanism searches for objects to store in the database, it will detect both Employee and Manager objects."*

**Dịch:** Giả sử bạn định nghĩa một inherited annotation `@Persistent` báo rằng **object của một class lưu được vào database**. Khi đó **subclass của các persistent class tự động được annotate là persistent**. Khi cơ chế persistence tìm object để lưu vào database, nó sẽ **phát hiện cả object `Employee` lẫn `Manager`**.

### `@Repeatable`

> *"As of Java 8, it is legal to apply the same annotation type multiple times to an item. For backward compatibility, the implementor of a repeatable annotation needs to provide a container annotation that holds the repeated annotations in an array."*

**Dịch:** **Từ Java 8**, **áp cùng một annotation type nhiều lần lên một item là hợp lệ**. Để **tương thích ngược**, người implement một repeatable annotation phải **cung cấp một container annotation giữ các annotation lặp lại trong một array**.

> *"Here is how to define the @TestCase annotation and its container:"*

```java
@Repeatable(TestCases.class)
@interface TestCase
{
    String params();
    String expected();
}

@interface TestCases
{
    TestCase[] value();
}
```

> *"Whenever the user supplies two or more @TestCase annotations, they are automatically wrapped into a @TestCases annotation."*

**Dịch:** Bất cứ khi nào người dùng **cung cấp từ hai annotation `@TestCase` trở lên**, chúng **tự động được bọc vào một annotation `@TestCases`**.

> **Caution (sách):** *"You have to be careful when processing repeatable annotations. If you call getAnnotation to look up a repeatable annotation, and the annotation was actually repeated, then you get null. That is because the repeated annotations were wrapped into the container annotation."*
>
> *"In that case, you should call getAnnotationsByType. That call "looks through" the container and gives you an array of the repeated annotations. If there was just one annotation, you get it in an array of length 1. With this method, you don't have to worry about the container annotation."*
>
> **Dịch:** **Phải cẩn thận khi xử lý repeatable annotation.** Nếu bạn gọi **`getAnnotation`** để tra một repeatable annotation, mà annotation đó **thật sự bị lặp lại**, thì bạn **nhận về `null`** — vì **các annotation lặp lại đã bị bọc vào container annotation**.
>
> Trường hợp đó bạn nên gọi **`getAnnotationsByType`**. Lời gọi này **"nhìn xuyên qua" container** và trả về **một array các annotation lặp lại**. Nếu **chỉ có một annotation**, bạn nhận nó trong **array độ dài 1**. Với method này bạn **không phải bận tâm tới container annotation**.
