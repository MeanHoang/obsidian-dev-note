## There Will Be Code
Tóm gọn **rất ngắn gọn** như sau:
=> **Code sẽ không bao giờ biến mất.**
**Vì sao?**
- Code chính là **cách diễn đạt requirement ở mức máy có thể hiểu và chạy được**
- Dù dùng mô hình, DSL, low-code hay AI sinh code → **cuối cùng vẫn phải chính xác, chi tiết, và formal**
- Khi một yêu cầu đủ chi tiết để máy thực thi → **nó đã là code**
**Kết luận:**Có thể ít “viết tay” hơn, nhưng **không thể loại bỏ sự chính xác** — mà sự chính xác đó chính là **code** ✅

## Bad Code
- **Code xấu tích lũy → giết tốc độ → giết sản phẩm → giết công ty**
- Ta viết code xấu vì:
    - Muốn nhanh
    - Áp lực
- Nhưng:
    - “Để sau sửa” gần như **không bao giờ xảy ra**
> ❝ Code xấu giống như nợ — vay thì dễ, trả thì cực, và lãi suất tăng dần ❞

## The Total Cost of Owning a Mess
- Code bẩn **không chỉ xấu**, mà:
    - Làm team chậm dần
    - Gây lỗi dây chuyền
    - Khiến dự án không cứu được
- Thêm người **không cứu nổi code rác**
- Áp lực chỉ làm mọi thứ **tệ hơn**
> ❝ Code bẩn giống như cát lún: càng giãy, càng lún sâu ❞

## The Grand Redesign in the Sky
- Code xấu → dev nổi loạn → đòi viết lại
- Viết lại:
    - Tốn thời gian
    - Không giải quyết gốc rễ
- Hệ thống mới **vẫn sẽ nát** nếu không giữ sạch
- Viết lại thường kéo dài nhiều năm
- **Clean code là để tồn tại lâu dài**
> ❝ Bạn không thể thoát khỏi code rác bằng cách viết thêm code rác mới ❞

## Attitude
- Code rác không phải do “số phận”
- Dev **có phần trách nhiệm rất lớn**
- Bổn phận của dev là:
    - Nói thật
    - Bảo vệ chất lượng code
- Viết code bẩn để chạy deadline = **thiếu chuyên nghiệp**
> ❝ Lập trình viên chuyên nghiệp bảo vệ code  
> giống như bác sĩ bảo vệ ca phẫu thuật ❞

## The Primal Conundrum
❝ Muốn nhanh, đừng làm ẩu — hãy làm sạch ❞ ✅
## The Art of Clean Code
- Muốn clean code → phải hiểu clean là gì
- Nhận ra code bẩn ≠ biết viết code sạch
- Clean code đến từ:
    - Kỹ thuật
    - Kỷ luật
    - Code-sense
- Dev giỏi giống như **nghệ sĩ**, không phải thợ gõ code. Tóm lại, một lập trình viên viết code "sạch đẹp" thật sự là một nghệ sĩ. Họ có thể tạo ra các hệ thống thân thiện chỉ từ một màn hình trống rỗng.
> ❝ Clean code không đến từ cảm hứng, mà đến từ luyện tập ❞ ✅

## What is Clean code 
1. Clean code **đọc thấy thích**
2. Logic rõ → bug khó trốn
3. Ít phụ thuộc → dễ bảo trì
4. Quan tâm từng chi tiết nhỏ
5. Code xấu lôi kéo code xấu hơn
6. **Mỗi phần code chỉ làm một việc và làm thật tốt**
> ❝ Clean code không chỉ đúng — nó có nhân cách ❞ ✅

## Schools of Thought
- Clean Code trong sách này = **trường phái của Uncle Bob**
- Không phải chân lý tuyệt đối
- Nhưng là:
    - Kinh nghiệm thật
    - Được kiểm chứng lâu dài
- Có thể không đồng ý
- Nhưng **xứng đáng để học và suy ngẫm**
> ❝ Clean Code không phải luật trời —  
> nó là kết tinh của kinh nghiệm ❞ ✅

## We Are Authors
**Clean Code không phải để “đẹp”, mà để “đi nhanh mà không tự bắn vào chân mình”.**

## The Boy Scout Rule 
**“Leave the campground cleaner than you found it.”**
- Nếu chúng ta làm cho code sạch hơn mỗi khi chúng ta kiểm tra nó, nó sẽ không thể lên mùi. Việc dọn dẹp không phải là thứ gì đó to tát: đặt lại một cái tên khác tốt hơn cho biến, chia nhỏ một hàm quá lớn, đá đít vài sự trùng lặp không cần thiết, dọn dẹp vài điều kiện if,...
- Đừng làm nó hoàn hảo hãy làm nó có trách nghiệm

## Conclusion
📚 **Sách không thể biến bạn thành nghệ sĩ — hay lập trình viên giỏi — ngay lập tức.**
- Sách chỉ có thể:
    - Chỉ ra **cách nghĩ**
    - Chia sẻ **kỹ thuật, công cụ, thói quen**
    - Cho bạn **xem ví dụ tốt – xấu – cách sửa**
- Còn việc **giỏi thật hay không** → **phụ thuộc vào bạn luyện tập**
👉 Clean Code **không hứa**: cho bạn “code-sense” (trực giác viết code sạch)
👉 Clean Code **chỉ hứa**
- cho bạn thấy **những dev giỏi suy nghĩ thế nào**
- họ **refactor ra sao**
- họ **nhìn code bẩn và cải thiện nó như thế nào**
