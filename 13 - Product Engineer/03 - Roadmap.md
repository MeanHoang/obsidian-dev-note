# 🗺️ Roadmap: Developer → Product Engineer

> Học qua **thực hành tại công việc hiện tại**, không phải học academic.
> Tổng ~9–12 tháng, nhưng giai đoạn 4 là liên tục cả sự nghiệp.

## Giai đoạn 1 — Hỏi "Tại sao" (1–2 tháng)
**Mục tiêu:** Bỏ thói quen code ngay khi nhận ticket.

- [ ] Mỗi ticket, trước khi code viết 3 dòng: *Vấn đề gì? User nào? Không làm thì sao?*
- [ ] Đọc *Shape Up* + *The Mom Test* ([[04 - Reading list]])
- [ ] Tập đặt câu hỏi ngược lại PO thay vì nhận spec một chiều

**Dấu hiệu đạt:** Bạn bắt đầu thấy khó chịu khi nhận yêu cầu mà không hiểu "why".

## Giai đoạn 2 — Định hình Scope (2–3 tháng)
**Mục tiêu:** Biết cắt MVP và viết requirement rõ ràng.

- [ ] Viết "1-pager" cho mỗi feature: Problem → Goal → Non-goals → MVP → Edge cases → Metric
- [ ] Tập phân loại [[06 - Frameworks|MoSCoW]] cho mọi feature
- [ ] Đọc *The Lean Product Playbook*
- [ ] Áp dụng [[02 - Checklist phân tích Feature]] cho mọi task

**Dấu hiệu đạt:** Bạn chủ động đề xuất cắt scope và giải thích được lý do.

## Giai đoạn 3 — Tư duy hệ thống & business rule (3–4 tháng)
**Mục tiêu:** Đặt logic đúng chỗ + hiểu metric SaaS.

- [ ] Học domain modeling nhẹ: entity, state, nơi đặt business logic (xem bước 6 [[02 - Checklist phân tích Feature]])
- [ ] Học đọc metric SaaS: funnel, **activation, retention, churn, MRR**
- [ ] Tham gia buổi product/planning, đặt câu hỏi về *why* và *priority*
- [ ] Đọc *Inspired* (chọn lọc) + *Continuous Discovery Habits*

**Dấu hiệu đạt:** Bạn nói được "feature này tác động tới retention thế nào".

## Giai đoạn 4 — Drive feature end-to-end (liên tục)
**Mục tiêu:** Tự sinh ra feature từ quan sát, không chờ giao việc.

- [ ] Tự đề xuất 1 feature từ quan sát data/user
- [ ] Viết spec → thuyết phục team → ship → **đo kết quả**
- [ ] Học nói ngôn ngữ business: *"giảm X% support ticket"* thay vì *"code clean hơn"*
- [ ] Dùng [[06 - Frameworks|RICE]] để bảo vệ thời gian khỏi feature vô giá trị

**Dấu hiệu đạt:** Team hỏi ý kiến bạn về *nên làm gì*, không chỉ *làm thế nào*.
