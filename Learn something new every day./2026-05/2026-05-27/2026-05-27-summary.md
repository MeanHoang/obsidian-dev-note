## 🔥 Top 3 đáng đọc nhất
1. **[Cloud Run Worker Pools GA + CREMA autoscaler queue-aware (Cloud Next '26)](https://cloud.google.com/blog/products/serverless/whats-new-for-cloud-run-at-next26)** — Worker Pools là loại resource Cloud Run **mới cho workload pull-based, non-HTTP** (xử lý queue, batch, AI inference) chạy "always-on" thay vì scale theo HTTP request. Kèm đó Google open-source **CREMA** (Cloud Run External Metrics Autoscaler) để scale worker theo tín hiệu ngoài như **Pub/Sub backlog hoặc Kafka lag**. Đây gần như đo ni cho kiến trúc Joy (Cloud Run + Pub/Sub): worker tiêu thụ event loyalty có thể tự co giãn theo độ tồn đọng hàng đợi thay vì hack `minInstances`.
2. **[Andrej Karpathy gia nhập Anthropic (19/05)](https://www.axios.com/2026/05/19/anthropic-openai-karpathy-andrej-claude)** — Karpathy (đồng sáng lập OpenAI, cựu trưởng nhóm computer vision Autopilot của Tesla, nay là nhà giáo dục AI có ảnh hưởng) về Anthropic làm ở team **pre-training** và lập đơn vị mới dùng chính Claude để tăng tốc nghiên cứu pretraining. Tín hiệu Anthropic hút được talent đỉnh giữa cuộc đua frontier — củng cố lý do đặt cược dài hạn vào hệ Claude/Claude Code mà bạn dùng daily.
3. **[Cloud Functions for Firebase giờ deploy theo region của data source, không mặc định us-central1 (Firebase CLI 15.17.0)](https://firebase.google.com/support/releases)** — Từ CLI 15.17.0, function được deploy vào region của **trigger data source** (Firestore/Storage) khi suy ra được, thay vì luôn nhét vào `us-central1`. Đây là cái bẫy latency/egress kinh điển: function trigger Firestore ở `asia-southeast1` nhưng chạy ở Mỹ. Nên **set region tường minh** trong định nghĩa function của Joy để tránh lệ thuộc suy luận.

## 🔥 Firebase & GCP
- ⭐ **[Cloud Run Worker Pools GA + CREMA (queue-aware autoscaling)](https://cloud.google.com/blog/products/serverless/whats-new-for-cloud-run-at-next26)**
  **Đây là gì:** Worker Pools = resource Cloud Run cho tác vụ nền pull-based (đọc message queue, batch job, AI inference) — không nhận HTTP traffic nên scale theo HTTP request không hợp; thay vào đó dùng **CREMA** (vừa open-source) để autoscale theo metric ngoài: số message tồn trong Pub/Sub, lag của Kafka. Cũng tại Next '26: Cloud Run thêm GPU NVIDIA RTX PRO 6000 Blackwell (serve model 70B+, scale-to-zero).
  **Vì sao đáng đọc:** Joy đang Cloud Run + Pub/Sub. Worker tiêu thụ event (earn points, sync order, tier recalc) hiện thường phải tune `minInstances`/`maxInstances` thủ công hoặc trigger qua Cloud Functions. Worker Pools + CREMA cho mô hình "consumer co giãn theo backlog hàng đợi" — đúng pattern cần khi BFCM dồn event đột biến.
- **[Firebase CLI 15.17.0 — region-aware function deploy + search index cho Firestore (07/05)](https://firebase.google.com/support/releases)**
  **Đây là gì:** Bản CLI thêm: (1) tạo **search index cho Cloud Firestore** từ CLI; (2) deploy function theo region của data source thay vì mặc định `us-central1`; (3) fix MCP tools + multi-database. Google khuyến nghị set region tường minh trong code function.
  **Vì sao đáng đọc:** Nếu Firestore của Joy đặt ở region châu Á mà function vẫn ngầm chạy `us-central1` thì mỗi trigger là 1 vòng round-trip xuyên lục địa (latency + egress cost). Upgrade CLI và pin region là quick win; search index từ CLI giúp script hoá thay vì click console.

## 🛒 Shopify Platform & API
- ⭐ **[`cartToken` field mới trên `Order` object (GraphQL Admin API, 12/05)](https://shopify.dev/changelog)**
  **Đây là gì:** Order object trong GraphQL Admin API giờ trả `cartToken` — token của cart đã tạo ra order đó, đạt parity với REST API (trước đây REST có, GraphQL thì không).
  **Vì sao đáng đọc:** Joy có thể nối **cart → order** để attribution chính xác hơn: gắn loyalty event ở tầng cart (apply reward, preview points) rồi reconcile với order khi checkout xong, mà không cần tự sinh/đối chiếu token thủ công. Hữu ích cho dedupe khi 1 cart sinh nhiều order hoặc abandoned-cart recovery.
- **[Nhiều product discount áp trên cùng 1 cart line (API 2026-04, 30/04)](https://shopify.dev/changelog)**
  **Đây là gì:** Version 2026-04 GraphQL Admin API cho phép stack **nhiều product discount trên một dòng cart**, mở rộng khả năng discount để hỗ trợ merchant **migrate khỏi Shopify Scripts trước hạn sunset 30/06/2026**.
  **Vì sao đáng đọc:** Deadline Scripts 30/06 đang đến gần — nếu logic reward chồng nhiều giảm giá của Joy còn dựa vào Scripts, đây là khả năng API cần để chuyển sang Functions. Nên rà sớm các program đang stack discount để không kẹt sát hạn.
