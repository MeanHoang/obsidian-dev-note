## 🏗️ System Design / Architecture
- ⭐ **[A Guide To Event-Driven Architectural Patterns](https://blog.bytebytego.com/p/a-guide-to-event-driven-architectural)** ([ByteByteGo](https://blog.bytebytego.com/p/a-guide-to-event-driven-architectural), 14/05)
  **Đây là gì:** EDA (event-driven architecture) là kiểu thiết kế nơi service giao tiếp qua "event" (bản ghi việc-đã-xảy-ra) thay vì gọi nhau trực tiếp; producer không bị block bởi downstream. Bài đi qua 6 pattern giải quyết các vấn đề EDA đẻ ra (ordering, duplicate, state transfer…). *(Phần chi tiết 6 pattern cần subscription.)*
  **Vì sao đáng đọc:** Joy đang xài Pub/Sub + Firestore triggers — đúng "xương sống" EDA. Hiểu pattern (Event-Carried State Transfer, Choreography, CQRS) giúp tránh tight-coupling khi scale event consumer.

## 🔥 Firebase & GCP
- **[Best practices for Cloud Firestore](https://firebase.google.com/docs/firestore/best-practices)** ([firebase.google.com](https://firebase.google.com/docs/firestore/best-practices))
  **Đây là gì:** Doc chính thức — tránh document ID tăng dần đơn điệu (`Customer1, 2, 3…`) gây hotspot ghi; chọn database location gần user/compute để giảm latency; cẩn trọng số lượng real-time listener vì ảnh hưởng cả performance lẫn billing.
  **Vì sao đáng đọc:** Refresher hữu ích trước khi thiết kế collection mới cho Joy — ID strategy + listener count là 2 chỗ dễ phá cost/perf nhất ở production.

## 🌐 Web Development
- **[Vitest 4.1 — Test Tags, native Node.js execution, AI Agent Reporter](https://www.infoq.com/news/2026/05/vitest-4-1-ai-agents/)** ([InfoQ](https://www.infoq.com/news/2026/05/vitest-4-1-ai-agents/), 01/05 — note: ra đầu tháng, chưa note)
  **Đây là gì:** Vitest là test framework gốc-Vite. 4.1 thêm: **Test Tags** (lọc/cấu hình nhóm test, vd `--tags-filter='frontend && !flaky'`), `viteModuleRunner: false` chạy bằng native Node import (khởi động nhanh, sát production hơn), hook `aroundEach/aroundAll`, và **reporter `agent`** giảm token khi chạy test trong AI coding agent (ẩn output của test pass).
  **Vì sao đáng đọc:** Reporter `agent` đáng thử nếu bạn chạy test qua Claude Code — đỡ ngốn context. Test Tags giúp tách nhanh test flaky khỏi CI gate.

## 🛒 Shopify Platform & API
- ⭐ **[Next Generation Events — developer preview](https://shopify.dev/changelog/next-generation-events-now-available-in-developer-preview)** (19/05)
  **Đây là gì:** Webhook/event đời mới. `_changed` liệt kê đúng field nào đã đổi (kèm path + ID); `_filter` bỏ qua delivery không khớp điều kiện (vd chỉ bắn cho product `active`); payload do bạn định nghĩa bằng Admin GraphQL query. Hiện ở API `unstable`, mới có topic Product & Customer.
  **Vì sao đáng đọc:** Joy nghe webhook Shopify để cập nhật điểm/loyalty. Field-level trigger + `_changed` cắt được lượng lớn event rác (vd merchant đổi tag/title không liên quan), giảm tải Cloud Run worker và logic dedupe.
- **[Function run log details tự hiện theo access scope](https://shopify.dev/changelog/function-run-log-details-are-now-automatically-visible-with-the-right-access-scopes)** (13/05)
  **Đây là gì:** Nếu app có scope đọc các field trong input query của Function, run log hiện luôn trong Dev Dashboard, không cần merchant bật share.
  **Vì sao đáng đọc:** Debug Shopify Functions (discount/shipping) trên store thật nhanh hơn hẳn — bớt 1 vòng đi nhờ merchant.
