# News Summary — 2026-05-05

## 🔥 Top 3 đáng đọc nhất
1. **[Axios npm bị compromise — UNC1069 (NK-nexus) cài WAVESHAPER.V2 backdoor](https://cloud.google.com/blog/topics/threat-intelligence/north-korea-threat-actor-targets-axios-npm-package)** — Đây là gì: từ ngày 31/03 (00:21–03:20 UTC), maintainer của `axios` (HTTP client phổ biến nhất trong JS, ~100M+ lượt tải/tuần) bị chiếm tài khoản và phát hành 2 version độc hại (`1.14.1`, `0.30.4`). Payload chèn dependency giả `plain-crypto-js@4.2.1` chạy SILKBELL dropper rồi cài WAVESHAPER.V2 backdoor cho cả Windows/macOS/Linux. Unit 42 update mới ngày **01/05** xác nhận đây là 1 trong 2 chiến dịch đang active (cùng Mini Shai-Hulud SAP). Tổng hợp Joy phải làm: **rà tất cả lockfile** xem có 2 version trên không, **rotate token** nếu CI từng `npm install` trong tháng 4, set `npm config set ignore-scripts true` cho prod build.
2. **[Chrome 148 stable ra hôm nay (05/05)](https://developer.chrome.com/blog/chrome-148-beta)** — Đây là gì: Chrome 148 lên stable chính thức ngày 05/05/2026. Feature đáng dùng cho dev: **name-only container queries** (declare query không cần `container-type` — viết responsive component gọn hơn), **`<video>`/`<audio>` lazy loading** native (không cần Intersection Observer thủ công), **`@supports at-rule()`** function (feature-detect at-rule như `@container style()`), **WebAuthn Immediate UI mode** (passkey sign-in flow gọn hơn), **Prompt API** access on-device Gemini Nano (Android), SharedWorker chôtphục hồi trên Android. Joy có UI extension trên Polaris/Customer Account → tận dụng container queries không cần `container-type` hack.
3. **[Cloud Run release notes tháng 5 — Worker pools GA + Compute flexible CUDS + disable run.app URL Preview](https://docs.cloud.google.com/run/docs/release-notes)** — Đây là gì: bản release notes mới nhất chốt loạt update tháng 5: **Worker pools GA** (deploy job dạng "always-on worker" thay vì request-driven, dùng cho consumer Pub/Sub/Kafka long-lived), **Compute flexible committed use discounts** giờ phủ Cloud Run service (CPU always-allocated) + Cloud Run jobs (1 commitment chia sẻ giữa Compute Engine + GKE + Cloud Run), **disable default `run.app` URL** Preview (chỉ truy cập qua LB/IAP, hợp với policy private), Ruby 4.0 Preview, **Cloud Run integrations bị discontinued** khỏi console + CLI (service đã deploy vẫn chạy nhưng không setup mới được).

## 🔥 Firebase & GCP
- ⭐ **[Cloud Run release notes — Worker pools GA, CUDS, disable run.app](https://docs.cloud.google.com/run/docs/release-notes)** (chi tiết ở Top 3)
  **Vì sao đáng đọc cụ thể cho Joy:**
  - **Worker pools GA**: nếu Joy có consumer Pub/Sub xử lý webhook order/refund liên tục → cân nhắc chuyển từ Cloud Run service (request-driven) sang Worker pools để bỏ overhead cold start + tận dụng concurrent processing rẻ hơn.
  - **Compute flexible CUDS**: nếu Joy đã có baseline CPU thường trực trên Cloud Run (admin internal service luôn chạy) → 1 commitment chung Compute Engine + Cloud Run có thể cắt 20-40% bill compute predictable.
  - **Cloud Run integrations discontinued**: nếu setup từ console "Add integration" (Firebase Hosting + Cloud Run, custom domain mapping qua wizard) — không lập mới được nữa, dùng từng service trực tiếp.

## 🛒 Shopify Platform & API
- ⭐ **[Multiple product discounts per cart line — API 2026-04 (changelog 30/04)](https://shopify.dev/changelog)**
  **Đây là gì:** từ API 2026-04, một line item trong cart có thể nhận **nhiều product discount** chồng nhau (trước đây chỉ 1). Shopify đẩy thay đổi này để hỗ trợ merchant migrate khỏi **Shopify Scripts** (Ruby checkout script) trước deadline tắt 30/06/2026 — Scripts hỗ trợ stack discount rất linh hoạt mà Functions chưa kịp đuổi.
  **Vì sao đáng đọc:** Joy nếu có Functions trả nhiều discount cho cùng line → giờ không bị clamp về 1. Cần test lại UI hiển thị tổng giảm giá trên cart/checkout vì nhiều discount cùng line có thể vượt giá gốc nếu logic không cap. Cũng là cờ báo: bất kỳ merchant nào còn dùng Scripts cho stack discount → Joy có thể đề xuất port sang Functions trong tháng 5-6.
- **[Actor field cho subscription contract + billing attempt mutations (changelog 04/05)](https://shopify.dev/changelog)**
  **Đây là gì:** mọi mutation `subscriptionContract*` và `subscriptionBillingAttempt*` giờ trả thêm field `actor` ghi rõ **ai khởi tạo action** (`CUSTOMER`, `MERCHANT`, `PARTNER`, `SHOPIFY_SYSTEM`). Trước đây phải đoán từ context.
  **Vì sao đáng đọc:** Joy nếu có audit log subscription event → chuyển sang đọc field `actor` thay vì heuristic (vd "request từ admin token = MERCHANT"). Đỡ debug khi merchant complain "ai cancel subscription của customer X?".
- **[Monitor admin web vitals trong Dev Dashboard (changelog 04/05)](https://shopify.dev/changelog)**
  **Đây là gì:** Shopify Dev Dashboard giờ thu thập **Core Web Vitals** (LCP, INP, CLS) cho admin embedded app — đo trực tiếp từ user thật trên store. Trước đây phải tự instrument Web Vitals + ship lên analytics riêng.
  **Vì sao đáng đọc:** Joy admin app embedded trong Shopify Admin → bật theo dõi để biết page nào INP/LCP cao, optimize trước khi reviewer Built for Shopify check (BfS scorecard có CWV).
- **[Default `appliesOnSubscription = true` cho app discount input (changelog 04/05)](https://shopify.dev/changelog)**
  **Đây là gì:** mọi mutation tạo discount qua app từ giờ mặc định **áp dụng cho cả subscription order**. Trước đây phải set thủ công `appliesOnSubscription: true`.
  **Vì sao đáng đọc:** breaking-ish change cho merchant không muốn discount stack vào subscription. Audit Joy: nếu code đang tạo discount qua API mà **không set explicit field này** → giờ tự động áp subscription, có thể giảm doanh thu recurring. Set explicit `false` nếu cần giữ behavior cũ.
- **[Analytics metric targets trong GraphQL Admin API (changelog 29/04)](https://shopify.dev/changelog)**
  **Đây là gì:** API mới CRUD cho **merchant metric target** — cho phép app set goal (vd "doanh thu tháng = 100k", "AOV = 80") rồi report progress. Tích hợp vào dashboard analytics merchant.
  **Vì sao đáng đọc:** loyalty app như Joy có thể set target gamified cho merchant (vd "100 customer redeem reward tháng này") và surface ngay trong Shopify Admin Analytics, không cần dựng UI riêng.

## 🔒 Security
- ⭐ **[Axios npm — UNC1069 supply chain (Google Threat Intel 01/04, Unit 42 update 01/05)](https://unit42.paloaltonetworks.com/monitoring-npm-supply-chain-attacks/)** (chi tiết Top 1)
  **Action checklist Joy hôm nay:**
  - `grep -r "axios.*1\.14\.1\|axios.*0\.30\.4" package*.json` — confirm không có version độc.
  - `npm ls plain-crypto-js` — check không có dependency giả này anywhere.
  - Nếu có: rollback về `axios@1.14.0` hoặc `1.15+` (đã clean), rotate mọi credential từng được đọc bởi process chạy npm install trong tháng 4.
  - Long-term: cân nhắc pin axios qua `package-lock.json` integrity hash, chuyển sang `fetch` native nếu chỉ cần GET/POST đơn giản (giảm attack surface).
- **[CISA alert: Supply Chain Compromise Impacts Axios Node Package Manager (20/04)](https://www.cisa.gov/news-events/alerts/2026/04/20/supply-chain-compromise-impacts-axios-node-package-manager)**
  **Đây là gì:** CISA — cơ quan an ninh mạng Mỹ — chính thức ra alert về incident axios. Liệt kê IOC + remediation steps cho doanh nghiệp Mỹ. Đây là incident npm thứ 3 CISA alert trong 6 tháng gần nhất.
  **Vì sao đáng đọc:** signal mức độ nghiêm trọng (CISA chỉ alert khi widespread impact). Nếu Joy có khách enterprise Mỹ cần report compliance → reference CISA alert ID là cách giải thích chuẩn.
