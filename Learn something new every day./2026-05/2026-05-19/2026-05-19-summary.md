## 🔥 Top 3 đáng đọc nhất
1. **[Shopify ra mắt Checkout & Accounts Configuration API — gộp branding 3 surface vào 1 API (2026-04)](https://shopify.dev/changelog/checkout-and-accounts-configuration-api-for-unified-branding-across-checkout-customer-accounts-and-sign-in)** — Thay thế hoàn toàn Checkout Profile API + Checkout Branding API (đã deprecated). 2. **[Shopify Engineering: "We replaced Redis with MySQL for inventory reservations—and it scaled"](https://shopify.engineering/scaling-inventory-reservations)** — Case study Emilie Noel (12/05): Shopify migrate inventory reservation từ Redis về MySQL 8, đỉnh BFCM 2025 chạm **$5,1 triệu doanh thu/phút**. Mẹo chính: `SKIP LOCKED` (lock-free queue trên row), composite PK `(shop_id, item_id, group_id, id)`, bounded pool 1000 row/item. Bottleneck thật ra là **connection management**, không phải query. Joy: pattern áp dụng được cho job queue trong Firestore/Cloud SQL khi có tranh chấp.
3. **[CVE-2026-42945 "NGINX Rift" — memory corruption, đang bị khai thác trong thực tế](https://www.helpnetsecurity.com/2026/05/18/ngnix-vulnerability-exploited-cve-2026-42945/)** — Disclosed 18/05. Memory corruption trong NGINX Open Source + Plus với rewrite config cụ thể, attacker gửi HTTP request đặc biệt → DoS hoặc unauth RCE. Joy chạy app trên Cloud Run nên upstream NGINX không lộ ra, nhưng nếu có Cloud Run service tự host NGINX (vd proxy custom domain) phải audit version + rewrite rules ngay.

## 🏗️ System Design / Architecture
- ⭐ **[We replaced Redis with MySQL for inventory reservations—and it scaled](https://shopify.engineering/scaling-inventory-reservations)** ([Shopify Engineering](https://shopify.engineering/scaling-inventory-reservations))
  **Đây là gì:** Case study Shopify (12/05/2026) về việc move khỏi Redis Lua scripts sang MySQL 8. Dùng SKIP LOCKED — feature cho phép `SELECT ... FOR UPDATE SKIP LOCKED`, transaction nào không lấy được row sẽ bỏ qua thay vì chờ → biến table thành queue song song không deadlock.
  **Vì sao đáng đọc:** Reframe insight quan trọng: "ở scale lớn, connection pool & lock granularity quan trọng hơn DB tốc độ raw". Mindset áp dụng cho mọi job queue / counter ở Joy (loyalty points redemption race condition).

## 🔒 Security
- **[CVE-2026-42945 NGINX Rift — đang bị khai thác (18/05)](https://www.helpnetsecurity.com/2026/05/18/ngnix-vulnerability-exploited-cve-2026-42945/)** ([Help Net Security](https://www.helpnetsecurity.com/2026/05/18/ngnix-vulnerability-exploited-cve-2026-42945/))
  **Đây là gì:** Memory corruption trong NGINX Open Source + Plus khi có rewrite config nhất định. HTTP request đặc biệt gây DoS hoặc unauth RCE.
  **Vì sao đáng đọc:** Cloud Run/Firebase Hosting không tự host NGINX nên Joy ổn — nhưng bất kỳ Cloud Run service nào dùng NGINX làm reverse proxy custom domain phải update ngay + rà rewrite rules.
- **[CVE-2026-42897 Microsoft Exchange Server zero-day OWA XSS — confirmed exploited](https://securityaffairs.com/192204/security/cve-2026-42897-microsoft-confirms-active-exploitation-of-exchange-server-zero-day.html)** ([Security Affairs 15/05](https://securityaffairs.com/192204/security/cve-2026-42897-microsoft-confirms-active-exploitation-of-exchange-server-zero-day.html))
  **Đây là gì:** XSS trong Exchange OWA, attacker gửi email crafted, victim mở OWA → JS chạy. Microsoft đang đưa mitigation tạm trước khi patch chính thức.
  **Vì sao đáng đọc:** Joy không host Exchange, nhưng nếu team dùng Outlook OWA (self-host hoặc Exchange Online tier có OWA exposed) cần đề phòng phishing email gửi tới hộp thư công ty.
