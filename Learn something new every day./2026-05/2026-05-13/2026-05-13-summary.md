# News Summary — 2026-05-13

## 🔥 Top 3 đáng đọc nhất

1. **[Chrome 149 beta — BFCache giờ chấp nhận trang có WebSocket, `element.scrollTo()` trả Promise, CSS gap decorations](https://developer.chrome.com/blog/chrome-149-beta)** — Đây là gì: Chrome 149 beta lên ngày 06/05/2026, stable 02/06/2026. Loạt feature web platform: trang có WebSocket open giờ vào được Back/Forward Cache (đóng connection khi cache vào, restore khi quay lại), `element.scrollTo()` / `scrollBy()` trả Promise resolve khi cuộn xong, CSS gap decorations cho phép kẻ đường giữa các ô grid/flex như `column-rule` lâu nay chỉ có cho multi-column. **Impact Joy Loyalty:** widget loyalty embed trên storefront thường mở socket realtime — sau khi user back từ checkout về, page reload chậm vì bị skip bfcache. Sau Chrome 149 stable: tự dưng được lợi mà không cần đổi code, miễn UX có thể chịu việc socket bị đóng-mở lại khi quay lại.

2. **[Firestore + Firebase Auth chính thức build full-stack bằng natural language trong Google AI Studio, deploy 1-click qua Cloud Run (GA)](https://firebase.google.com/docs/ai-assistance/ai-studio-integration)** — Đây là gì: Google AI Studio Build mode giờ tự detect khi app cần data/auth, tự setup Firebase project, sinh file `firebase.ts` + `firestore.rules` + sign-in flow rồi deploy server-side code lên Cloud Run — chuỗi này GA tại Cloud Next 26 (xem [Cloud Run announcements](https://cloud.google.com/blog/products/serverless/whats-new-for-cloud-run-at-next26)). **Impact Joy Loyalty:** prototype/spike feature mới (vd. dashboard merchant analytics) giờ có thể vibe-code rồi đẩy thẳng vào Cloud Run cùng stack production của Joy — không phải maintain template Express riêng nữa. Cẩn thận review Security Rules AI-generated trước khi ship thật.

3. **[Shopify Inventory Adjustments giờ có full audit trail (07/05/2026)](https://changelog.shopify.com/posts/inventory-adjustment-workflow-now-with-full-change-tracking)** — Đây là gì: khi adjust tồn kho trong admin sẽ có 2 mode — **Set To** (đặt số mới, Shopify tự track delta) và **Adjust By** (chọn source + destination cho movement). Mọi adjustment giờ ghi nguyên source, destination, user, timestamp, lưu vĩnh viễn (bỏ giới hạn 180 ngày cũ). **Impact Joy Loyalty:** nếu Joy có flow grant point dựa trên restock / inventory event, source/destination/userId mới mở data point cho rule "thưởng cho staff adjust kho đúng quy trình" hoặc audit-based loyalty. Webhook payload inventory_levels/update đáng kiểm tra lại xem có field mới không.
