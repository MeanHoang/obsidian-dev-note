## 🔥 Firebase & GCP
- ⭐ **[Cloud Run release notes — April 2026](https://docs.cloud.google.com/run/docs/release-notes)**
  **Đây là gì:** Nhiều feature mới **GA** trong tháng 4: (1) **Remote MCP server** — deploy AI agent dùng Model Context Protocol lên Cloud Run; (2) **Worker pools** — service chạy background job có queue; (3) **IAP trực tiếp trên Cloud Run** — không cần Load Balancer để secure endpoint; (4) runtime: Go 1.26, Python 3.14, Java 25, .NET 10, PHP 8.5; (5) **CREMA open-source** — autoscaler cho worker pool dựa trên Pub/Sub backlog / Kafka lag.
  **Vì sao đáng đọc:** Joy Loyalty backend chạy trên Cloud Run Functions. IAP GA nghĩa là bỏ được Load Balancer trước Cloud Run khi chỉ cần internal auth → giảm cost. Worker pools + CREMA = pattern sạch cho job xử lý webhook async thay vì Cloud Tasks.
- **[Firestore release notes — Regional endpoints GA + Pipeline operations](https://docs.cloud.google.com/firestore/docs/release-notes)**
  **Đây là gì:** (1) **Regional/Multi-regional endpoint GA** — request được route đảm bảo trong region DB → compliance data-residency tốt hơn. (2) **Pipeline operations** (preview từ 01/2026) — 100+ query feature mới: server-side aggregation phức tạp, array unnesting, giống SQL. (3) **MongoDB-compat mode** thêm **change streams** — realtime listener giống Firestore snapshot.
  **Vì sao đáng đọc:** Joy Loyalty có merchant EU → regional endpoint GA chắc chắn request không leak region. Pipeline operations có thể thay thế BigQuery export cho một số dashboard aggregation đơn giản.
- **[Firestore Pipeline Operations — Firebase Blog](https://firebase.blog/posts/2026/01/firestore-enterprise-pipeline-operations/)**
  **Đây là gì:** Deep-dive official về query engine mới. Pipeline = chain stage xử lý document (filter, aggregate, project, unnest array) chạy server-side. Available preview cho Android/iOS/web/admin SDK.
  **Vì sao đáng đọc:** Dashboard "top 10 merchant by points issued" hiện phải fetch data rồi aggregate client — pipeline làm server-side, tiết kiệm document read + network.

## 🔒 Security
- **[KelpDAO bridge exploit $292M → $14B DeFi TVL exodus](https://www.coindesk.com/tech/2026/04/19/2026-s-biggest-crypto-exploit-kelp-dao-hit-for-usd292-million-with-wrapped-ether-stranded-across-20-chains)** (19-20/04/2026)
  **Đây là gì:** KelpDAO (liquid restaking protocol trên Ethereum) bị exploit **$292M** qua LayerZero bridge: attacker drain 116,500 rsETH (~18% supply). Root cause: dùng **single DVN** (decentralized verifier network) thay vì multi-DVN → single point of trust. DeFi TVL rơi từ $99.5B → $85.21B trong 2 ngày (~$14B rút ra), Aave mất $10B deposit. Preliminary attribution: Lazarus Group (DPRK).
  **Vì sao đáng đọc:** Lesson architect: **bất kỳ cross-service trust check nào cũng phải multi-party** (multi-DVN, multi-oracle, quorum). Tương đương Firestore security rules — đừng trust 1 claim duy nhất, đặc biệt từ external system.
