## 1. Khái quát lại workflow: bug-check và joy-ship

### 1.1. Hiện trạng: 2 skill chồng chéo nhau

| Việc | Đang nằm ở đâu | Vấn đề |
|---|---|---|
| Bug merchant (prod) | `/bug-check`: 3 chân (vấn đề, code, setting) → 1 trong 4 verdict → **dừng** | Chỉ chẩn đoán. Sửa thì "nhảy" sang main checkout hoặc `/feature-open` |
| Bug tester (UAT trên branch) | `joy-ship` chế độ **STABILIZE** | Công thức TDD tôi hay dùng (đọc setting → test fail → pass) **không nằm trong skill nào** |
| Feature (Notion) | `joy-ship` chế độ **SHIP / CONTINUE** | Gate dày, review nhiều tầng |

**Mâu thuẫn ngay trong skill so với cách tôi đang làm:**

| # | Skill đang ghi | Thực tế / mong muốn hiện tại |
|---|---|---|
| 1 | joy-ship dòng 67: *"LUÔN làm ở main checkout, KHÔNG worktree"* (quy định 18/06) | Đã chuyển sang Orca: **mỗi task một worktree** (chốt 28/09) |
| 2 | joy-ship dòng 81, 289, 356: *"AI không test browser, anh tự test"* (quy định 17/08) | Muốn **AI test và báo bằng ảnh**. Skill cũng tự mâu thuẫn: dòng 110 lại ghi "one combined browser pass" |
| 3 | Review: mỗi phase `/review` + `/code-review`, thêm verify nền (a) và (b), Step 5 `/review-v2` + `/impact`, Step 7 thêm 4 agent | Muốn **1 vòng** + 1 agent trace hidden dependency (#7) |
| 4 | joy-ship dòng 158: *"mỗi sub-step 2a/2b/2c/2d một session mới"* | Muốn **sub agent** thay cho session mới (#2) |
| 5 | bug-check: *"không branch, không worktree, 1 session"* | Thực tế vẫn mở workspace Orca riêng cho bug-check |

### 1.2. Đề xuất: MỘT khung chung, 3 loại việc chỉ khác ở bước nào được bỏ qua

**7 khối dùng chung** (mỗi khối là một file nhỏ trong skill, các luồng gọi lại, không viết lại):

| Khối | Làm gì | Ai chạy |
|---|---|---|
| **K0 Mở việc** | worktree từ `master`, harness đủ, kiểm tra auth (gcloud/GitLab/SA), `process.md` | parent |
| **K1 Đọc bằng chứng** | 3 chân: vấn đề · code (`file:line`, trên đúng branch) · setting thật (MCP joy → Chrome admin → Chrome storefront) | sub agent (fan-out khi bug khó) |
| **K2 Tái hiện** | FE: Chrome chụp **ảnh bug** · BE: viết test/script **FAIL** | sub agent verifier |
| **K3 Sửa** | FE: thử override live trước → rồi code · BE: code cho test **PASS** (cấm hard-code) | sub agent implementer |
| **K4 Xác nhận** | FE: chụp **ảnh sau** · BE: test pass + chạy lại test cũ | sub agent verifier |
| **K5 Review 1 vòng** | Joy `/review` (đọc `process.md` + chuẩn riêng) + 1 agent trace hidden dependency | 2 sub agent song song |
| **K6 Commit** | tôi nói "commit nhé" → chỉ file của task, message tiếng Anh | parent |
| **K7 Ship** | push → MR → deploy staging → pipeline xong thì Chrome test lại → báo bằng ảnh | parent + sub agent |

**3 loại việc = 3 cách đi qua 7 khối:**

| Loại | Lệnh | Đi qua | Dừng hỏi tôi ở đâu |
|---|---|---|---|
| **Bug merchant** (prod) | `/bug-check` | K0 → K1 → **verdict** → (nếu `fix`) K2 → K3 → K4 → K5 → K6 | sau verdict · trước commit |
| **Bug tester** (UAT, nhiều bug) | `/joy-ship` STABILIZE | K0 → lặp **từng bug**: K1 → K2 → K3 → K4 → **K6 commit bug đó** → hết lô: K5 **một lần** (finding thành commit sửa riêng) → K7 | khi có trade-off thật · mỗi commit · trước push |
| **Feature** (Notion) | `/joy-ship` SHIP | K0 → Gate 1 Hiểu → Gate 2 Plan → lặp **từng phase**: K3 → K4 → K6 → hết phase: K5 **một lần** → K7 | Gate 1 · Gate 2 · mỗi commit · trước push |

**Điểm khác cũ:**
- Công thức TDD (K2 → K3 → K4) **dùng chung** cho mọi loại, không còn chỉ nằm trong lời tôi dặn.
- Review (K5) chỉ **1 lần ở cuối lô**, không chạy mỗi phase.
- Mọi bước "đọc" và "làm" do **sub agent** chạy. Parent chỉ điều phối, verify và hỏi tôi.
- Bug merchant khi `fix` được đi tiếp **trong cùng skill**, không phải nhảy sang main checkout.

### 1.3. Việc cần làm để khái quát
> ✅ **Đã làm 28/09** — 8 khối ở `.claude/workflow/blocks/K0…K7`; `joy-ship` 382 → 111 dòng, `bug-check` 129 → 59 dòng, thành bản đồ gọi khối; đã xoá hết luật lỗi thời ("không worktree", "anh tự test", review mỗi phase, verify nền, Step 7 4 agent, session mới mỗi sub-step). `feature-team` / `feature-open` gắn DEPRECATED.
1. Tách 7 khối thành file trong `.claude/skills/_blocks/` (hoặc tên khác), mỗi khối ≤ 1 trang.
2. Viết lại `bug-check` và `joy-ship` thành **bản đồ gọi khối**, bỏ các đoạn trùng.
3. Xoá các quy định đã lỗi thời: "không worktree", "anh tự test", "session mới mỗi sub-step", review mỗi phase.
4. Lệnh vẫn giữ nguyên (`/bug-check`, `/joy-ship`) để không phải học lại.

## 2. Các bước — theo thứ tự làm

| 5 | **Trùng chức năng / bản sao cũ**: `devStackOwners.mjs` của team (27/09) vs `kill-dev`/`dev-local-light`/`local-dev` của tôi; `bug-check` vs `/debug`/`/fix`/`support-triage`; `.codex/` chụp từ 21/08 | — | skill cũ lệch với cơ chế mới |

**Nguyên tắc:**
- **Lớp team** (kiến thức domain, luật layer, agent implementer, hook an toàn): **dùng nguyên, không sửa**.
- **Lớp của tôi** (workflow, gate, review, style): **ghi đè lớp team ở MỘT chỗ duy nhất, nạp sau cùng.**

**Làm gì:**
1. Tạo **`CLAUDE.local.md`** (Claude Code 2.1.283 vẫn hỗ trợ file này: nạp cùng CLAUDE.md, không commit). Nội dung ngắn, chỉ ghi các điểm ghi đè:
   - Điều phối: `joy-ship` / `bug-check` + sub agent. **Bỏ qua khối `orca-lanes` / `cmux-workflow`**, không mở lane Codex.
   - Review = `/review` chạy trong sub agent + 1 tracer; **không** dùng `code-reviewer` thay thế.
   - Commit theo luật riêng (mỗi commit chờ "commit nhé", message tiếng Anh).
   - Dev: dùng cơ chế `devStackOwners` của team (không tự `kill-port`).
2. Thêm `CLAUDE.local.md` vào `.git/info/exclude`. Bootstrap / `/sync-harness` copy nó sang mọi worktree.
3. Bootstrap / `/sync-harness` chép **bản `auto-lint` của tôi** sang worktree (giữ `skip-worktree` như repo gốc).
4. Bootstrap cảnh báo khi **CLAUDE.md của worktree cũ hơn `origin/master`** (vd: "worktree này đang dùng CLAUDE.md từ 23/08").
5. Đồng bộ `kill-dev` / `dev-local-light` / `local-dev` theo `devStackOwners.mjs` (gộp với A4 và 5.3: **dùng lại cơ chế giữ cổng của team**, không tự viết khoá mới nếu nó đã đủ).
6. `.codex/`: tôi không chủ động dùng Codex → xoá qua `/joy-disk-cleanup junk` (5.4).
- **Xong khi:** mở một worktree bất kỳ → hỏi AI *"review dùng gì, điều phối thế nào?"* → trả lời theo lớp của tôi; sửa một file cũ → diff chỉ có dòng đã sửa.

## 5. Giải đáp 4 thắc mắc

### 5.1. Role + bộ tiêu chuẩn "sống" (thắc mắc 1)

**Mỗi role là 1 file** `.claude/roles/<role>.md`, gồm đúng 6 mục:

| Mục | Nội dung |
|---|---|
| Làm gì | 1–3 dòng |
| Không được làm gì | vd verifier không sửa code, reviewer không đọc lý do của người viết |
| Đầu vào | nhận gì từ parent (process.md, diff, bug số mấy…) |
| Đầu ra | trả về đúng dạng gì (bảng `file:line`, 2 ảnh, test fail/pass…) |
| Khi nào dừng | báo parent, không tự đi tiếp |
| **Tiêu chuẩn** | checklist, mỗi dòng ghi **ngày + câu gốc của tôi** làm nguồn |

**Danh sách role:**

| Role | Việc |
|---|---|
| parent | điều phối, verify, hỏi tôi, commit |
| scout | đọc code / setting / log |
| implementer (BE / admin FE / widget) | sửa code |
| verifier | chụp ảnh, viết test fail → pass |
| reviewer | Joy `/review` |
| tracer | tìm hidden dependency giữa các surface |
| decider | `feature-reviewer`: đáng làm không, làm thế nào |

**Cách bộ tiêu chuẩn tự lớn lên:**
1. Tôi sửa lưng một agent (vd *"sao lại đặt tên chung chung thế"*).
2. Parent soạn **1 dòng tiêu chuẩn** + role áp dụng rồi hỏi tôi: *"Thêm vào tiêu chuẩn `implementer`?"* (vì hook `memory-consent`, không tự ghi).
3. Tôi gật → append vào file role, kèm ngày + câu gốc.
4. **Một dòng bị vi phạm lại lần 2** → đẩy xuống tầng cứng hơn (hook hoặc test), theo đúng luật của note 1.
5. Cứ 2 tuần chạy lại [[scan-ai-friction.py]] → lỗi mới lặp nhiều thì thành dòng tiêu chuẩn mới.

**Quan hệ với memory:** các `feedback_*` về cách code, review, đặt tên → **chuyển** vào tiêu chuẩn của role tương ứng. Memory chỉ giữ thứ về **con người tôi** (ngôn ngữ, cách giải thích, cách làm việc).

**Vì sao cách này tốt hơn memory:** parent dán **đúng file role** vào prompt khi giao việc, nên sub agent đọc tiêu chuẩn ngay đầu context. Memory thì nằm lẫn trong 50 mục và dễ bị lờ đi.

### 5.2. Workflow chi tiết: scout khi nào, gọi role nào, grill me khi nào (thắc mắc 2)

| Bug đã commit | xoá `tmp/shots/` của bug đó (ảnh đã gửi tôi trong chat) |
| Mockup đã được duyệt | giữ **1 file đã chọn**, xoá các bản còn lại |
| MR đã merge / task xong | chuyển task vào `archived/`, **chỉ giữ 5 file GIỮ**, xoá `tmp/` |
| Worktree không dùng nữa (branch đã merge) | xoá `node_modules` (~3,6 GB) + gỡ worktree |

**Skill `/joy-disk-cleanup`** — một lệnh cho mọi việc dọn:

| Gọi | Dọn gì |
|---|---|
| `/joy-disk-cleanup` | quét hết, in bảng **cái gì · dung lượng · vì sao được xoá** → tôi gật từng nhóm → mới xoá |
| `/joy-disk-cleanup worktree` | worktree có branch **đã merge** hoặc lâu không mở: xoá `node_modules` (~3,6 GB/worktree), gỡ worktree (`git worktree remove`), **không bao giờ** đụng worktree còn thay đổi chưa commit |
| `/joy-disk-cleanup ship` | `tmp/` của task đã xong, mockup thừa, archive task đã merge (giữ 5 file GIỮ) |
| `/joy-disk-cleanup junk` | `.playwright-cli/`, `.codex/`, file rác một lần (hỏi từng mục) |

- **Luật an toàn:** chỉ xoá sau khi tôi gật; worktree có diff chưa commit hoặc chưa push → bỏ qua và báo; không xoá worktree đang giữ khoá dev (5.3).
- **Nhắc tự động:** khi mở workspace mới mà đĩa trống **ít hơn dung lượng một lần `yarn install`** (~3,6 GB) → gợi ý chạy `/joy-disk-cleanup worktree` trước khi cài.

**Dọn một lần hiện tại (cần tôi duyệt từng mục):**
1. `.codex/`: còn dùng Codex không? Không thì xoá, còn thì thêm vào `.git/info/exclude`.
2. `.playwright-cli/`: xoá (Playwright đã bỏ cho app testing).
3. `loyalty-page-from-shop/designs/`: thêm vào exclude, hoặc chuyển vào `tmp/`.
4. Ảnh và HTML cũ trong `.claude/ship/*`: chạy `/joy-disk-cleanup ship` lần đầu.
